# 分包 04：流程状态机与人工审批需求要件

## 1. 独立交付说明

本分包定义根任务的生产状态机、失败和人工分支、阶段创建条件、状态转换审计、并发控制和审批节点。负责架构师必须给出可验证的状态转换合同，不负责各业务产物内部内容。

## 2. 主流程边界

```text
需求生产/门禁 → 要件生产/门禁 → 架构生产/门禁
→ 详细设计生产/门禁 → 实现/代码门禁 → 测试/测试门禁
→ 质量总审 → 发布 → 复盘
```

失败统一进入 `FAILED → CLASSIFYING → CORRECTING → RETESTING → REGATE_CHECKING`；人工分支统一进入 `BLOCKED → WAITING_FOR_HUMAN`。

## 4. 输入、输出和异常

- 输入：当前状态与版本、触发事件、产物/Gate 摘要、审批和权限上下文。
- 输出：原子状态变更、阶段创建或明确拒绝，以及相应审计事件。
- 前置：状态版本一致，动作在允许转换表内。
- 后置：状态、审计和后续任务一致提交。
- 异常：并发冲突、审计失败、未知状态、失效产物或审批不足均 fail-closed。

## 5. 分包验收

架构交付必须包含完整状态表、事件、守卫条件、副作用、失败码、幂等键、并发策略、审批表、恢复和取消路径；用自动化测试覆盖每条允许与禁止转换。
