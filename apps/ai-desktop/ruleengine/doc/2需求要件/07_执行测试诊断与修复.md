# 分包 07：执行、测试、诊断与修复需求要件

## 1. 独立交付说明

本分包从执行脑领取已批准 Architecture Package 开始，覆盖任务执行、实际测试、独立 Gate 失败后的诊断和有上限修复，止于原 Gate 复验或人工接管。

## 2. 角色和流程

```text
Planning → Development → Code Gate → Test → Test Gate
FAIL → Diagnosis(A/B/C/D) → 对应 Fix → 受影响重测 → 原 Gate
超限/高风险/无法分类 → 人工接管
```

## 4. 输入、输出和异常

- 输入：有效 Architecture Package、tasks、固定规则/Gate、工作空间和权限。
- 输出：实际变更、执行/测试/修复/Review 文档、证据、Gate 结果或人工接管请求。
- 前置：包未过期，任务可执行，工作区和分支一致。
- 异常：上游合同错误、超范围、证据不足、环境不安全、Gate 自身失败或预算超限均阻断。

## 5. 分包验收

架构交付必须包含任务执行器、范围守卫、测试证据模型、数据隔离、覆盖率策略、分类与路由、问题指纹、修复上限、原 Gate 复验和人工接管的完整时序。
