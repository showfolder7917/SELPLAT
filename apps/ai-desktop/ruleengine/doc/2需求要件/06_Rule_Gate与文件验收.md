# 分包 06：Rule、Gate 与文件验收需求要件

## 1. 独立交付说明

本分包定义 Rule 的指导职责、Gate 的独立执法职责、规则规模治理、固定快照、基础 Gate、文件类型验收和 Gate 结果生命周期。它不定义具体业务方法实现。

## 2. 核心边界

- Rule 回答“应该怎样做”，使用中文核心原则。
- Gate Definition 定义可机械判断的输入、算法、PASS/FAIL、违规和证据。
- Gate Runner 在独立控制面执行定义，只裁决、不修复。
- 稳定生产 Rule 硬上限为 30 条；Gate 数量不限但必须治理版本和成本。

## 4. 异常与修复

1. Gate 检测产物缺陷：进入对应产物 Fix Agent，返回原 Gate Definition 版本复验。
2. Gate 自身漏检或误检：形成 Gate 改进提案，不得为了当前任务临时改结果。
3. Rule 冲突、重复或失效：形成 Rule 提案，经独立 Gate 与审批后发布新版本。
4. 当前任务继续使用冻结快照，除非通过正式变更和影响评估重新发布。

## 5. 分包验收

架构交付必须包含 Rule/Gate 数据合同、唯一索引、快照、15 个基础 Gate 注册、文件类型扩展机制、Runner 隔离、证据存储、结果失效和治理发布流程。
