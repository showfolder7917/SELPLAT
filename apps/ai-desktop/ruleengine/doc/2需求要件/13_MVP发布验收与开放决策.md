本分包定义第一阶段 MVP 边界、发布条件、端到端验收和必须由人工确认的开放决定。总体架构师应以此作为各分包汇总和进入详细设计前的最终检查表。

## 3. 发布包最小内容

发布包必须包含交付范围、根任务和版本、全部产物清单、测试和 Gate 摘要、审计完整性、已知限制、未决风险、回滚/恢复说明和审批引用。任何产物变化后发布包及引用的 Gate 结果必须重新生成。

## 5. 架构汇总验收

1. 每个 `REQ-*` 都映射到至少一个架构对象且只有一个所有者。
2. 所有跨分包接口、事件和数据关系使用稳定 ID，不依赖文件顺序或聊天上下文。
3. 所有 Must 要件都有可执行验证方案；未量化部分已关联 `DEC-*`。
4. 任何待定决定不得被伪装为已批准技术事实。
5. 总体架构、各分包架构和 Architecture Package 使用同一要件版本和摘要。

## 6. 进入详细设计的条件

本目录全部文件通过 Requirements Definition Gate、`DEC-*` 的阻断项已完成批准、所有 `REQ-*` 状态改为 `approved`、架构 Gate 对固定摘要 PASS 后，才允许进入详细设计。当前 V1.0-draft 不满足该条件。
