# 分包 01：双工程系统边界架构要件

## 1. 目标与范围

本分包把 AI 产出工厂划分为本地 Python 工程 `memory` 和服务器 Java HTTP 工程 `ai-factory`。它定义产品级边界、数据所有权、信任关系和故障隔离，供两个工程的架构师独立设计。

## 2. 系统职责矩阵

| 能力 | memory 本地工程 | ai-factory 服务工程 |
| --- | --- | --- |
| 用户需求接入与文档生成 | 主责 | 登记任务、版本和状态 |
| 需求/架构/执行 Agent | 主责运行 | 保存角色版本和授权上下文 |
| Codex、文件、Git、测试 | 主责 | 保存摘要、状态、结果与证据引用 |
| Rule/Gate/Process 生成与验证 | Rule Factory、索引/冲突/依赖检查、规则包构建、Codex 联动验证和本地 Runner | 不生成、不运行，只接收候选包和验证证据 |
| Rule/Gate/Process 正式发布 | 提交候选包并只加载摘要匹配的批准版本 | 权威审批、版本登记、发布状态和受控分发 |
| 根任务与阶段状态机 | 本地显示和请求转换 | 唯一权威状态与转换者 |
| 文件内容 | 本地工作空间权威 | 默认只保存元数据、摘要和受控上传件 |
| 实时页面、集中查询 | 可有本地视图 | 服务端权威 API、SSE 和管理页 |
| 数据库 | 仅本地运行状态/队列 | 业务权威数据库唯一写入 |

## 3. 架构要件

| ARC ID | 来源要件 | 所属 | 架构约束 | 验收方式 |
| --- | --- | --- | --- | --- |
| ARC-CTX-001 | REQ-SCP-001～REQ-SCP-004 | 共同 | 两工程必须共同形成从需求到交付的一个产品流程，任一阶段对象都使用统一稳定 ID 和版本合同。 | 端到端系统上下文评审。 |
| ARC-CTX-002 | REQ-SCP-005～REQ-SCP-006 | 共同 | 新体系不得依赖迁移或替代原规则引擎，也不得自动批准高风险动作或未审批治理版本。 | 范围与权限 Gate。 |
| ARC-CTX-003 | REQ-SCP-007～REQ-SCP-009 | 服务主责 | 服务端控制面必须以文件 Gate、阶段 Gate、测试、审计和审批共同决定流转，不能由本地成功响应替代。 | 跨工程失败场景测试。 |
| ARC-CTX-004 | REQ-SCP-010、REQ-NFR-001 | 共同 | 30 分钟仅为端到端服务目标；两端必须分别记录耗时，任何超时策略不得跳过质量步骤。 | 性能追踪评审。 |
| ARC-CTX-005 | REQ-AGT-008～REQ-AGT-009 | memory/服务 | 架构脑和执行脑在 memory 内以角色与阶段隔离；独立控制面位于服务端，交接只使用版本化产物和结构化合同。 | 越权与交接测试。 |
| ARC-CTX-006 | REQ-RUN-001、REQ-RUN-006、REQ-RUN-013 | 服务 | 服务端 Java 是业务数据库唯一写入者；Python 无业务表凭证，只能通过 HTTP 请求状态变化。 | 连接和权限扫描。 |
| ARC-CTX-007 | REQ-DAT-001～REQ-DAT-012 | 共同 | 服务端拥有根任务、流程、治理和追踪权威数据；本地拥有工作空间文件、执行过程和待同步队列，双方禁止双主。 | 数据所有权矩阵 Gate。 |
| ARC-CTX-008 | REQ-ART-003～REQ-ART-004、REQ-ART-011 | memory | 工作空间、需求分支和运行证据只在本地工程边界内创建，服务端不得直接挂载或改写本地目录。 | 路径和远程访问测试。 |
| ARC-CTX-009 | REQ-GAT-001～REQ-GAT-013 | memory 生成/执行，服务审批/聚合 | memory 的 Rule Factory 生成并验证 Rule/Gate/Process 包、运行文件型 Gate；服务端只登记批准版本、分发匹配摘要并聚合 Gate 结果。 | 候选包发布、摘要匹配与本地 Runner 测试。 |
| ARC-CTX-010 | REQ-AUD-001～REQ-AUD-012 | 共同 | 本地记录原始执行事实并可靠上报；服务端保存集中审计链和查询索引，任何一端都不得覆盖历史。 | 断网补报与哈希链测试。 |
| ARC-CTX-011 | REQ-NFR-003～REQ-NFR-004 | 共同 | 网络和服务故障必须局部隔离；本地可继续受控执行已批准且未过期包，但不能创建新权威状态或自行 Gate。 | 断网恢复演练。 |
| ARC-CTX-012 | REQ-NFR-006、REQ-NFR-009～REQ-NFR-011 | 共同 | 信任边界位于 HTTP 接口；跨边界数据必须认证、加密、脱敏、限权、可审计并使用工程相对标识。 | 安全架构 Gate。 |

## 4. 跨工程禁止事项

1. memory 直接连接服务端业务数据库。
2. ai-factory 通过共享盘、SSH 或绝对路径改写本地工作空间。
3. 两端各自生成同一 task_id、stage_thread_id 或治理版本号。
4. 本地把离线草稿声明为已批准，或服务端把未收到完整证据的执行声明为通过。
5. HTTP 失败后无幂等键重放高风险请求。

## 5. 依赖与输出

- 输入：158 条需求要件、用户确认的双工程决定。
- 输出：系统上下文、所有权矩阵、信任边界、跨工程 API/事件清单。
- 依赖：分包 05、09、10、12 完成接口、数据、安全与故障细化。
