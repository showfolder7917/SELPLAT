## 2. 已确认的最高级架构决策

1. `memory` 与 `ai-factory` 保持两个独立工程，不合并源码、构建、运行目录或数据库。
2. `memory` 是本地 Python AI 工厂，承载需求分析师、架构脑入口、本地 Agent 编排、Codex、本地工作空间、执行与证据采集。
3. `memory` 内置本地规则工厂，承载 Rule/Gate/Process 提案生成、索引与依赖检查、规则包构建、本地 Gate Runner 和 Codex 联动验证。
4. `ai-factory` 是未来部署到服务器的 Java HTTP 控制面，承载根任务权威状态、已批准治理包的登记与分发、审批、Gate 结果聚合、集中审计索引和实时查询；不生成规则、不运行 Codex。
5. 两个工程只通过版本化 HTTP API、稳定 ID、摘要和事件合同交互；禁止共享数据库、直接读取对方内部目录或形成隐式跨工程调用。
6. 服务端是业务状态、审批结果和已发布治理包版本的权威写入者；本地是规则工厂、工作空间文件和本地执行事实的所有者。本地规则候选与执行事实通过 API 上报后由服务端登记。
7. 服务不可用时，本地可保存未登记草稿、候选规则包和待上报事实，但不得把它们声明为已批准、已 Gate 或已进入下一阶段。

- 架构要件：`ARC-<范围>-<三位序号>`。
- 架构对象：`CMP-<范围>-<三位序号>`。
- 接口合同：`API-<范围>-<三位序号>`。
- 事件合同：`EVT-<范围>-<三位序号>`。
- 架构决定：`ADR-<三位序号>`；待确认决定：`ADEC-<三位序号>`。
- 所有架构要件状态为 `draft`；只有 Architecture Gate 和人工批准后才能进入详细设计。

## 6. 完成门槛

1. 158 条需求要件全部映射到至少一个 `ARC-*`。
2. 每个组件、API、事件和数据聚合有唯一所属工程。
3. 跨工程调用全部经过版本化 HTTP 合同，不存在共享数据库和目录读取。
4. 服务不可用、重复请求、版本冲突、摘要不一致和断线恢复均有明确结果。
5. 所有 `ADEC-*` 完成批准或明确排除在 MVP 外。
6. Architecture Gate 对固定文件摘要逐文件及聚合验收通过。
