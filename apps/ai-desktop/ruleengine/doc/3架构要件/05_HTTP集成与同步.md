# 分包 05：HTTP 集成与同步架构要件

## 1. 目标

本分包定义 memory 与 ai-factory 唯一允许的集成方式：版本化 HTTPS API、稳定身份、幂等写入、摘要校验、租约、outbox 补报和 SSE 查询。禁止共享数据库和跨工程文件访问。

## 2. 接口族

| API ID | 方向 | 用途 |
| --- | --- | --- |
| API-TSK-001 | memory → 服务 | 创建根任务、取得任务与阶段快照 |
| API-RUN-001 | memory → 服务 | 领取阶段运行、续租、心跳和释放 |
| API-ART-001 | memory → 服务 | 登记产物元数据、摘要和证据引用 |
| API-ERR-001 | memory → 服务 | 上报错误、测试、修复和完成事实 |
| API-GOV-001 | memory → 服务 | 提交本地生成的 Rule/Gate/Process 候选包、摘要、影响分析和验证证据 |
| API-GOV-002 | 服务 → memory | 返回审批结果、正式版本、发布状态，并分发与批准摘要一致的治理包 |
| API-APR-001 | 用户/服务 | 审批需求、要件、治理版本和高风险动作 |
| API-QRY-001 | 客户端 → 服务 | 查询任务、追踪、审计和 SSE 进度 |

## 3. 架构要件

| ARC ID | 来源要件 | 架构约束 | 验收方式 |
| --- | --- | --- | --- |
| ARC-API-001 | REQ-RUN-003 | 所有跨工程能力必须登记 HTTP 方法、版本、路径、请求/响应 Schema、身份、权限、幂等、错误和兼容策略。 | OpenAPI Gate。 |
| ARC-API-002 | REQ-RUN-004 | 领取接口必须原子创建租约并返回 run_id、stage_thread_id、版本、有效期和续租策略。 | 双领并发测试。 |
| ARC-API-003 | REQ-RUN-005～REQ-RUN-006 | 快照接口必须返回角色、已批准治理包版本/摘要、Architecture Package 和工具权限；本地只激活与本地包摘要一致的批准版本，不能通过 API 直接设置状态。 | 权限与摘要匹配测试。 |
| ARC-API-004 | REQ-RUN-007～REQ-RUN-009 | 心跳和进度事件必须有单调序号、run_id、事件类型、时间和幂等键；百分比不是状态转换依据。 | 乱序/重复事件测试。 |
| ARC-API-005 | REQ-RUN-010 | SSE 支持 Last-Event-ID；重连先取得权威快照，再续订未消费事件。 | 断线恢复测试。 |
| ARC-API-006 | REQ-RUN-011～REQ-RUN-012 | 错误、产物和完成接口只接收事实，服务端异步或同步返回“已登记/需补充/冲突”，不返回伪 Gate PASS。 | 错误与完成合同测试。 |
| ARC-API-007 | REQ-WFL-009～REQ-WFL-010、REQ-NFR-004 | 所有写 API 使用稳定幂等键和状态版本；相同键同内容返回原结果，不同内容返回冲突。 | 幂等与冲突测试。 |
| ARC-API-008 | REQ-ART-006、REQ-ART-009 | 产物接口必须同时提交 artifact_type、相对标识、版本和摘要；摘要变化使关联验证失效。 | 摘要失效测试。 |
| ARC-API-009 | REQ-ART-008、REQ-ART-010 | Architecture Package 和变更请求必须用不可变版本获取/提交，禁止原地覆盖。 | 版本并发测试。 |
| ARC-API-010 | REQ-AUD-008～REQ-AUD-009 | API 只允许白名单字段，认证凭据和敏感正文不得进入请求日志和审计事件。 | 敏感信息扫描。 |
| ARC-API-011 | REQ-NFR-003、REQ-NFR-013 | memory 使用持久 outbox；网络失败指数退避，重连前校验租约和版本，不确定高风险动作转人工。 | 断网补报演练。 |
| ARC-API-012 | REQ-NFR-006 | 生产通信必须使用 TLS、服务端身份校验、短期客户端凭据、最小作用域和可撤销授权。 | 安全握手与撤销测试。 |
| ARC-API-013 | REQ-NFR-007～REQ-NFR-008 | API 使用兼容版本策略；新增字段向后兼容，破坏性变更发布新主版本并保留迁移窗口。 | 合同兼容性测试。 |
| ARC-API-014 | REQ-NFR-001～REQ-NFR-002 | 每类接口必须定义超时、重试、速率和负载上限，不能用无限等待阻塞本地工作。 | 压力与超时测试。 |
| ARC-API-015 | REQ-GAT-001～REQ-GAT-013、REQ-EVO-008～REQ-EVO-011 | 治理发布接口必须把候选内容生成与验证保留在 memory，仅上传受控包或摘要、依赖清单、Runner 版本和证据；服务端审批不得改写候选内容，只能批准、拒绝或要求新版本。 | 候选包提交、拒绝修改与正式版本测试。 |

## 4. 标准错误语义

- `400`：Schema 或业务字段无效。
- `401/403`：身份或权限不足。
- `404`：对象不存在或对调用者不可见。
- `409`：状态版本、摘要、幂等键内容或租约冲突。
- `410`：快照或 Architecture Package 已过期。
- `422`：请求合法但不满足阶段合同。
- `429`：受控限流，返回重试时间。
- `5xx`：服务故障；本地不得假定动作失败或成功，必须用幂等查询核对。

## 5. 数据传输边界

默认传输元数据、摘要、结构化事实和受控证据引用。完整源码、敏感文档和大体积测试证据只有在明确 artifact policy 与审批允许时上传。
