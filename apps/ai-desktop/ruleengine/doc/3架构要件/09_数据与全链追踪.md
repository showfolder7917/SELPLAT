# 分包 09：数据与全链追踪架构要件

## 1. 目标

本分包定义服务器权威业务数据、本地执行状态、跨工程标识、追踪关系和影响传播。物理 DDL、字段类型和索引由详细设计确定。

## 2. 数据所有权

| 数据 | 权威所有者 | 本地/服务端副本规则 |
| --- | --- | --- |
| 根任务、阶段、运行、审批 | ai-factory | memory 只读缓存 |
| 角色版本与审批状态 | ai-factory | memory 固定快照缓存 |
| Rule/Gate/Process 源文件、候选包和本地验证证据 | memory | 服务端仅接收受控包、摘要和证据 |
| 已批准治理包版本、摘要、替代与发布状态 | ai-factory | memory 保存摘要一致的已批准快照 |
| 工作空间文件、Git、命令和原始测试证据 | memory | 服务端保存摘要和受控引用 |
| 产物元数据、追踪、Gate 结果 | ai-factory | memory 可缓存当前快照 |
| 待上报事件和恢复点 | memory | 确认接收后按策略归档 |
| 集中审计链和查询索引 | ai-factory | memory 保存本地事实序列至确认上报 |

## 4. 一致性策略

跨工程不使用分布式数据库事务。服务端写入以 HTTP 幂等事务为边界；memory 使用 outbox 和服务端确认游标实现至少一次投递、服务端按幂等键实现效果一次。

## 5. 冲突策略

状态版本冲突、摘要冲突、租约失效和 Package 过期必须返回 409/410 并停止本地继续推进。自动合并只允许非权威展示字段，业务状态和正式产物不得静默覆盖。
