# 分包 13：MVP 与开放决策架构要件

## 1. MVP 边界

第一阶段必须验证本地 memory 与服务器 ai-factory 的最小闭环，但允许服务端先部署在本机或测试服务器；部署位置变化不能改变 HTTP 和数据所有权边界。

## 2. 架构要件

| ARC ID | 来源要件 | 架构约束 | 验收方式 |
| --- | --- | --- | --- |
| ARC-MVP-001 | REQ-MVP-001 | memory 建立五个入口和唯一索引，服务端登记其角色版本与摘要。 | 启动 Gate。 |
| ARC-MVP-002 | REQ-MVP-002 | 两端共同注册生产、门禁、修复、进化和支撑角色，并验证职责隔离。 | 角色权限测试。 |

## 3. 建议交付顺序

1. memory：五个入口、需求/要件 Agent、本地 Rule Factory、本地工作空间和同步客户端。
2. ai-factory：任务/阶段、身份、HTTP、数据库、治理包登记和审计最小服务。
3. 本地规则包构建、服务端审批登记、批准快照加载、产物登记和本地 Gate Runner 最小链路。
4. 执行、测试、失败修复、SSE 页面和全链追踪。
5. 真实低风险需求试运行与 34 项总验收。

## 5. 进入详细设计条件

需求要件与本架构要件均通过对应 Gate，ADEC 中阻断详细设计的事项完成批准，且两个工程的组件、API、数据、事件和部署对象有唯一所有者后，才允许进入详细设计。
