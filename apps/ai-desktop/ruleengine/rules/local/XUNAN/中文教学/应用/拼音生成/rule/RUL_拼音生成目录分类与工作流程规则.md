## 1. 适用范围

本规则用于从 DOC/DOCX 生成、检查、修正和归档可编辑拼音文档。读音取值与校正依据同时遵守 `RUL_拼音标注与朗读版校正规范.md`。

## 2. 固定目录边界

1. 核定成品直接平铺在 `OPTION/temp/中文教学/拼音生成/项目/成品`，不再按项目建成品子目录。
2. 源文档、项目特有参考、纠音词典和裁决记录只放 `OPTION/temp/中文教学/拼音生成/项目/项目资料/<项目名>`。
3. 转换副本、渲染图、比较文件、未核定 DOCX、日志和缓存只放 `OPTION/temp/中文教学/拼音生成/临时文件`。
4. 临时文件命名使用 `<项目名>__<阶段>__<说明>.<扩展名>`，阶段取 `转换`、`检查`、`候选`或 `日志`。
5. 只在实际有文件时建立分类目录，禁止保留空的工作、源文档、参考、配置或校正占位目录。

## 3. 新项目建立

1. 以书名或源文档内容集合命名项目，版本号不写入项目目录名。
2. 建立 `项目/项目资料/<项目名>`；核定文件将直接写入已有的 `项目/成品`。
3. 将现有文件按需放入 `源文档`、`参考资料`、`生成配置`或 `校正记录`；没有内容的分类不建目录。
4. 写 `项目说明.md`，记录源文档、参考资料、目标模式、成品命名和当前缺失项。

## 4. 生成流程

### 4.1 准备输入

- 源文档必须只读保留，生成目标不得与源文档同路径。
- 标引模式必须明确：默认为 `READING_TEACHING`，需要正词法本调版时显式使用 `ORTHOGRAPHY`。
- 生成前记录源文档哈希，后续确认其未被修改。

### 4.2 生成候选稿

- 工具只能将候选稿和中间资料写入外部统一临时目录。
- 多页文档必须按内容自然分页；诗词默认每首从新页开始，长篇允许跨页，不得通过过度缩小字体强行塞入一页。
- 第三方拼音库只生成候选，不能作为最终读音裁决。

### 4.3 自动检查

必须至少检查：

1. 源文档哈希前后一致。
2. DOCX ZIP 结构完整，Word XML 可正常解析。
3. 标题、作者、正文、标点、篇目数量和顺序与源文档一致。
4. 每个需注音汉字都有且只有一个对应拼音单元，不得错位、漏注或多注。
5. 多音字、通假字、人名、地名、词牌和古义按完整语境复核。
6. 字体、字号、行距、对齐、分页、表格边界和页边距逐页渲染检查，不得出现重叠、截断、压线、溢出、异常留白或孤行。
7. 拼音文本不得出现无效音节、丢失声调或 Word EQ 域代码。

项目长期使用的错误清单和读音裁决移入 `项目资料/<项目名>/校正记录`；仅用于当次比较的报告保留在统一临时目录。

### 4.4 异常处理

- 自动修复后必须重新进行同级别检查。
- 同一问题最多自动尝试 3 次；3 次仍失败时，将定位、尝试方法和临时文件路径写入 `项目资料/<项目名>/校正记录/待人工处理问题.md`。
- 单个篇目失败不得阻塞后续可处理篇目；记录失败后继续批量流程。
- 仅在源文档损坏、核心输入缺失、全部篇目映射不可用或继续会覆盖正式资料时，才停止整个任务。

### 4.5 核定与归档

1. 只有通过结构、内容、拼音映射和逐页视觉检查的文件才能进入 `项目/成品`。
2. 命名使用 `<内容名>（拼音版或注音版）核定版<序号>.docx`；成品名必须包含完整内容名与版本号，避免平铺后重名。旧 `.doc` 文件不伪装成 DOCX。
3. 成品写入后再检查哈希、数量、命名、可打开性和目标路径。
4. 更新 `项目资料/<项目名>/项目说明.md`中的当前成品版本及缺失输入。
5. 完成归档后，可在统一临时目录中按 `<项目名>__` 前缀筛选并清理本项目的可重建文件。

- [ ] 全部不可删除项目资料都在 `项目/项目资料`。
- [ ] 可重建文件全部位于唯一的 `OPTION/temp/中文教学/拼音生成/临时文件`。
- [ ] 不存在仅作占位用途的空目录。
- [ ] 无旧 `1参考/2原版/3输出/历史/成品` 扁平路径残留。
- [ ] 正式 DOCX 可解压、可打开，文档内容和页面检查通过。
- [ ] 可以安全按项目名前缀清理临时文件。
