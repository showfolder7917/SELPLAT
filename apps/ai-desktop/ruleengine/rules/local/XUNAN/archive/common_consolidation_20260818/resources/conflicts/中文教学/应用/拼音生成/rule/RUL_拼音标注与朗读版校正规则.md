# 拼音标注与朗读版校正规范

## 文档信息

- 规范版本：`1.5`
- 制定日期：`2026-07-18`
- 默认业务模式：`READING_TEACHING`（朗读教学版）
- 适用对象：儿童读物、小学及初中古诗文、蒙学读物、现代汉语短文及“拼音在上、汉字在下”的 DOCX
- 适用工具：本工程通用 Java 拼音生成工具、文档专用纠音词典、DOCX 定点修复工具和文档渲染检查工具
- 目标：让后续 AI、开发者和人工校对者使用同一证据层级、同一标引口径和同一验收流程，避免仅凭拼音库默认结果或个人语感改音

## 0. 当前实现、问题与优先修正项

### 0.1 当前已经具备的能力

当前工程已实现以下通用能力：

- `PinyinDocxGenerationTool`：从普通 DOCX 生成可编辑拼音 DOCX。
- `PinyinTextConverter`：按 Unicode 码点建立“一个汉字对应一个拼音单元”的映射。
- 第三方基础库：`com.github.houbb:pinyin:0.4.0`，用于生成初始候选拼音。
- 文档专用纠音词典：使用 UTF-8 TSV，以长词优先方式覆盖第三方库结果。
- `poetry` 模式：解析诗题、朝代、作者和正文，并按一首诗一页生成。
- 原文保护：生成前后检查源文件 SHA-256，禁止源文件和目标文件使用同一路径。
- 结构保护：词组字符数与拼音音节数不一致时直接失败，不允许静默错位。

当前主要文件：

- Java 入口：`apps/rule-engine/backend/src/main/java/com/sp/selplat/local/code/XUNAN/中文教学/拼音生成/PinyinDocxGenerationTool.java`
- 拼音转换：`apps/rule-engine/backend/src/main/java/com/sp/selplat/local/code/XUNAN/中文教学/拼音生成/PinyinTextConverter.java`
- 普通文档渲染：`apps/rule-engine/backend/src/main/java/com/sp/selplat/local/code/XUNAN/中文教学/拼音生成/PinyinDocxRenderer.java`
- 版式配置：`apps/rule-engine/backend/src/main/java/com/sp/selplat/local/code/XUNAN/中文教学/拼音生成/PinyinGenerationConfig.java`
- 诗词解析：`apps/rule-engine/backend/src/main/java/com/sp/selplat/local/code/XUNAN/中文教学/拼音生成/PoetryDocumentParser.java`
- 诗词渲染：`apps/rule-engine/backend/src/main/java/com/sp/selplat/local/code/XUNAN/中文教学/拼音生成/PoetryDocxRenderer.java`
- 古诗和三字经纠音词典：由当前项目提供经过核验的 UTF-8 TSV，并通过 `--dictionary` 显式传入；公共规则层不保留不存在的默认词典路径。

### 0.2 当前核心问题

1. 第三方拼音库只能生成候选，不能作为最终读音裁决依据。
2. 多音字、人名、地名、词牌名和古诗文特殊读音必须结合完整语境判断。
3. 当前工具没有显式区分“正词法本调版”和“朗读教学变调版”。
4. 当前两列 TSV 只保存结果，没有保存来源、版本、页码、裁决理由和争议状态。
5. `一、不` 的朗读变调主要依靠人工词典，容易漏标或误标。
6. 轻声不能仅按现代口语词组套用到古诗韵脚、专名或独立名词。
7. 同一词组在同一文档中若需要两个不同读音，当前“按词组全局覆盖”模型无法表达位置差异。
8. 旧 `.doc`、扁平 EQ 域和正常 DOCX 的修复方式不同，错误地重建整份文档可能破坏排版。

### 0.3 可以继续复用的结构

- 保留现有两列 `overrides.tsv`，避免破坏 Java 工具兼容性。
- 保留“长词优先”策略，用完整语境覆盖单字默认音。
- 保留逐码点对齐、源文件哈希保护、临时文件写出和原子替换原则。
- 为 TSV 增加同名的裁决记录文档，而不是直接扩展 TSV 列数。

建议配套文件：

```text
{document-name}-overrides.tsv
{document-name}-override-decisions.md
{document-name}-pinyin-checklist.md
```

### 0.4 后续工具升级前必须遵守的事项

1. 每次任务开始时显式声明标引模式，默认不得猜测。
2. 正式生成必须提供文档专用纠音词典，不能把无词典样稿直接交付。
3. 修改前先生成错误清单，明确“改什么”和“保留什么”。
4. 证据冲突或证据不足时不得自动修改，应标记为待人工核定。
5. 已生成 DOCX 只修拼音时，优先定点修改拼音文本节点，不得无故重建排版。

## 1. 规范目标

本规范需要保证：

- 读音有明确语境，不按单字默认音机械处理。
- 每一项人工覆盖都能追溯到标准、教材、辞书或正式专名来源。
- 朗读教学版能让儿童看到拼音后直接读出正确读音。
- “朗读变调”和“词汇本调”不会混为一谈。
- AI 只自动处理证据充分的项目，不用猜测填补争议。
- 修正仅影响拼音层，不改变原文、标点和版式。
- 检查结果可以由程序复核，而不是只依赖目视判断。

## 2. 输入与输出边界

### 2.1 输入

正式任务至少需要以下输入：

| 输入项 | 必填 | 说明 |
|---|---:|---|
| 原文文件 | 是 | 优先使用 `.docx`；旧 `.doc` 只作参考或先转换副本 |
| 输出文件 | 是 | 不得与原文文件同路径 |
| 标引模式 | 是 | `ORTHOGRAPHY` 或 `READING_TEACHING` |
| 文档类型 | 是 | 现代文、古诗词、蒙学、词牌、专名表等 |
| 目标读者 | 是 | 儿童朗读、普通读者、语言研究等 |
| 版式参考 | 按需 | 有参考版式时，参考文件是排版权威 |
| 纠音词典 | 正式生成必填 | 文档专用 TSV |
| 证据记录 | 正式核定必填 | 来源、版本、页码或网址、裁决理由 |

使用教材、教师教学用书或规范性辞书时，必须记录出版社、版次或年份、册次及页码；不得只记“人教版”或“某词典”。

### 2.2 输出

标准输出包括：

1. 拼音 DOCX 成品。
2. 文档专用纠音 TSV。
3. 读音裁决记录。
4. 修正前错误清单或检查报告。
5. 自动验证结果：数量、原文哈希、拼音差异、分页和渲染结果。

### 2.3 禁止扩大修改范围

只修拼音时，禁止修改：

- 汉字和标点。
- 标题、朝代、作者和正文顺序。
- 分页、页边距、字体、字号和表格宽度。
- 与目标读音无关的 OOXML 部件。
- 原版或参考文件。

## 3. 两种标引模式

### 3.1 `ORTHOGRAPHY`：国家正词法本调版

用途：辞书索引、标准拼写、语言数据交换和要求严格执行正词法本调的场景。

- `一、不` 一般标本调 `yī、bù`。
- 三声变调标本调。
- 轻声音节不标调号。
- 多音字仍必须按语义选择正确词汇音。

### 3.2 `READING_TEACHING`：朗读教学版

用途：儿童直接看拼音朗读、拼音启蒙、古诗文诵读辅助。

- `一、不` 按实际、稳定、可规则化的朗读变调标写。
- 三声变调仍标本调，不把语流中的第二声写进字面拼音。
- 轻声按规范词典或教材随文读音标写，轻声音节不加调号。
- 多音字、专名和古诗文读音先按语境裁决，再应用变调规则。

本项目默认使用 `READING_TEACHING`。

这一选择不违反 `GB/T 16159-2012`。该标准第 6.5.2 条规定“一、不”一般标原调，同时允许在语言教学等场景按变调标写；`GF 0015-2010` 也明确在教学词表中“一、不”标变调、三声变调标本调。

### 3.3 模式不得混用

同一成品不得出现以下混合状态：

- 部分“一、不”标本调，部分标实际变调，但没有明确原因。
- 部分连续第三声写实际第二声，其他位置保留第三声。
- 同一个轻声词在相同语境中一处有声调、一处无声调。

### 4.1 来源等级

| 等级 | 来源 | 使用范围 |

| L1 | 现行法律、国家标准、教育部和国家语委正式发布的规范 | 总体规则、审音、拼写、变调和轻声原则 |
| L2 | 当前任务对应版本的统编教材、教师教学用书、教材随文注音、人民教育出版社正式配套朗读 | 教材篇目的具体随文读音、古诗文教学口径 |

### 4.3 关于《普通话异读词审音表（修订稿）》

2016 年发布的是公开征求意见稿，不是已正式施行的新审音表。在没有检索到教育部或国家语委正式发布文件前：

- 不得把征求意见稿写成“现行国家标准”。
- 不得用征求意见稿单独推翻正式审音表或现行教材读音。
- 可以把征求意见稿作为争议背景记录，但证据状态必须标为 `DRAFT_ONLY`。

### 4.4 冲突裁决顺序

1. 新的、正式生效的专项规范优先于旧规范。
2. 正式文件优先于征求意见稿、新闻转载和搜索摘要。
3. 对指定教材篇目，教材随文注音和教师教学用书优先于通用拼音库。
4. 完整词组和完整句义优先于单字字典默认音。
5. 官方人名、地名资料优先于通用分词结果。
6. 同等级权威来源冲突时，不自动修改，进入人工核定。
7. 只为押古韵而恢复推测古音，不构成自动修改依据。

## 5. 拼音书写和逐字对齐规则

### 5.1 基本格式

- 使用带调号拼音：`zhǎng`，不使用 `zhang3`。
- 拼音文本使用 Unicode NFC 规范化。
- 使用 `ü` 及其带调形式，如 `nǚ、lǜ`；不得写成面向输入法的 `v`。
- 一个汉字对应一个拼音音节。
- 标点、空格、数字和拉丁字符不生成中文拼音，但保留原位置。
- 轻声音节不标声调，如规范词中的 `zi、tou、shang`。
- 单字上方展示模式统一使用小写；连续正词法拼写中的专名首字母大写规则不强套到逐字单元格。

### 5.2 声调符号位置

按《汉语拼音方案》执行：

- 有 `a` 标在 `a` 上。
- 无 `a` 有 `e` 标在 `e` 上。
- `ou` 标在 `o` 上。
- `iu、ui` 标在后一个元音上。
- `i` 加调号时去掉圆点。

### 5.3 教材拼音字形与英文字母区分

<!-- 问题：英文字体常把 ASCII `a` 渲染为双层字形，而小学拼音教学使用单层的拼音 `ɑ`；只检查拼写正确不能保证儿童看到的字形正确。 -->
<!-- 场景：拼音字母表、韵母教学、发音口形、音节拆分、PPT 圆形字母和其他需要突出展示拼音字母形态的儿童教学材料。 -->
<!-- 业务含义：儿童看到的拼音字形必须与教材书写一致，避免把英文 `a` 的字形误教成汉语拼音字母。 -->

1. 独立展示韵母或讲解字母形态时，必须使用单层教材拼音字形 `ɑ`，禁止使用英文字体显示的双层 `a`。
2. 在韵母组合、发音训练标题和拆分示范中，涉及该字母的内容必须写成 `ɑo、ɑn、ɑng` 等教材拼音形式；不得为了输入方便回退为会显示成英文双层字形的 `ao、an、ang`。
3. 完整音节和带调拼音必须保持规范拼写与声调位置，同时选用能稳定呈现教材拼音字形的字体；若目标字体把 `a、ā、á、ǎ、à` 显示为英文双层字形，必须更换为经过渲染验证的拼音教学字体或使用项目已核定的教材字形方案。
4. 字符正确不等于验收通过。DOCX、PPT 和图片成品都必须实际渲染，检查 `ɑ`、含 `a` 的带调音节及相邻韵母是否仍被字体替换为英文形态。
5. 自动检查至少覆盖：
   - 独立字母或韵母教学对象中残留的 ASCII `a`；
   - `ao、an、ang` 等发音教学标签是否已转换为教材拼音字形；
   - 带调音节所用字体是否属于项目已验证字体集合；
   - 最终渲染图中是否出现双层英文 `a`。
6. 普通英文单词、程序参数和非拼音拉丁文本不执行上述替换；检查器必须依据对象所在栏目、文本标签或教学语境判定，禁止全文件无差别替换。

### 5.4 拼音教学页的语义分区与排版检测

<!-- 问题：旧PPT抽取文本常把拼音、说明、汉字和标点拆成单字行；仅检查对象未越界仍可能生成行首标点、音汉错位和难以阅读的混排页面。 -->
<!-- 场景：韵母讲解、四声练习、词语练习、口形说明和其他同时出现拼音与汉字的PPT教学页。 -->
<!-- 业务含义：拼音正确只是底线，成品还必须让儿童能清楚识别发音方法、音节、对应汉字和练习词语。 -->

1. 拼音练习页必须至少分为“发音要领、四声练习、词语练习”三个独立教学区；禁止把说明、拼音、汉字和词语拼成一个连续文本块。
2. 旧稿中的多空格和碎片换行只能作为结构恢复线索，不得原样继承为目标排版；生成器必须先恢复“拼音音节—对应汉字”的逐组关系，再创建原生文本对象。
3. 拼音和汉字必须逐组居中对齐；四声音节不得串位，词语汉字数量必须与对应拼音音节数量一致。旧稿中的双空格不得直接认定为词界，因为同一词内部也可能存在双空格；必须结合本区总音节数、总汉字数和目标词组数量恢复完整词语，禁止把“白云”拆成“白 / 云”两张卡。
4. 逗号、句号、分号、顿号和冒号不得成为独立文本对象或出现在视觉行首；说明文字必须先清理标点前异常空格，再由文本框自然换行。
5. 拼音教学正文不得为塞入内容而缩小到 `18pt` 以下；信息量超过单页安全容量时，应调整分区比例、段落结构或受控拆页，不得用不可读小字规避溢出。
6. 自动检测至少覆盖：
   - 三个教学分区是否齐全；
   - 是否存在行首或孤立标点；
   - 是否存在超长单一文本块或异常文字密度；
   - 拼音音节与对应汉字是否同时存在且数量匹配；
   - 每张词语卡是否包含完整词语，检测器不得只验证单字存在而放过错误拆词；
   - 非页码教学文字是否小于最小字号；
   - 页面无几何越界后，是否仍存在语义混排或视觉不可读问题。
7. 自动检测通过后仍须渲染原始尺寸页面进行目视复核；“无溢出”不得替代可读性和教学对应关系验收。

### 5.5 原文对齐硬约束

```text
汉字码点数 = 拼音单元数 + 不注音原文单元数
```

每个汉字单元必须满足：

```text
PinyinCell(pinyin="带调或轻声拼音", text="原汉字", type=HANZI)
```

任何漏音、多音节挤入一个单元、一个音节跨两个汉字或标点被错误注音都必须失败。

## 6. 朗读教学版具体规则

### 6.1 多音字先判语义

必须按“完整词组 + 句义 + 词性 + 专名身份”判断，禁止按单字频率选择。

示例：

| 语境 | 正确读音 | 说明 |
|---|---|---|
| 春去花还在 | `hái` | 表示仍然 |
| 明月何时照我还 | `huán` | 表示返回 |
| 门泊东吴万里船 | `bó` | 船停靠 |
| 天似穹庐 | `sì` | 表示像 |
| 生当作人杰 | `dāng` | 表示应当 |
| 当银钲 | `dàng` | 表示当作 |

AI 必须先解释句义，再给读音结论。不能只写“这是多音字”。

### 6.2 人名、姓氏、地名和专名

- 姓氏按姓名身份判断，如“查慎行”的“查”不是普通动词读音。
- 地名必须查官方地名或教材注释，如“大柏地”“西塞山”。
- 词牌名、曲牌名和典籍名按专名读法处理，如“清平乐”“卜算子”“三传”。
- 作者名、朝代和标题也属于正式检查范围，不能只检查正文。
- 找不到 L2 至 L4 的直接证据时，状态设为 `REVIEW_REQUIRED`。

### 6.3 古诗文和通假字

1. 先确认当前教材文本，不擅自换成其他版本原文。
2. 当前教材有随文注音或教师用书说明时按教材执行。
3. 通假字按该句所表达的词义和教材口径读，不按字形默认音。
4. 古代专名、古代制度名、古义词可查《辞源》等权威古汉语辞书。
5. 不仅为了押韵而采用网络流传的古音，例如没有教材依据时不得把现代规范音改成推测古音。

### 6.4 “一”的朗读标引

先确定“一”在句中的语法作用，再按后续音节的本调判断。

| 条件 | 标音 | 示例 |
|---|---|---|
| 单独使用、词句末尾、序数、编号、数目逐位读 | `yī` | 其一、第一、编号“一零一”中的“一” |
| 后接四声 | `yí` | 一道 `yí dào`、一片 `yí piàn` |
| 后接一、二、三声 | `yì` | 一天 `yì tiān`、一年 `yì nián`、一水 `yì shuǐ` |
| 夹在重叠动词中且规范读轻声 | `yi` | 看一看；必须由词典或教材确认 |

注意：

- 标点后的字不跨越明显停顿触发变调。
- 先处理后一个字的多音字本调，再判断“一”的变调。
- 数字、序数、编号和独立列举不能仅看下一个汉字机械变调。

### 6.5 “不”的朗读标引

| 条件 | 标音 | 示例 |
|---|---|---|
| 后接四声 | `bú` | 不对 `bú duì`、不怕 `bú pà` |
| 后接一、二、三声，或单独使用、句末 | `bù` | 不飞、不成、不改 |
| 固定格式中规范读轻声 | `bu` | 好不好等口语结构；必须由词典或教材确认 |

先确定后字正确读音。例如“不应人”中的“应”先判为 `yìng`，再把“不”标为 `bú`。

### 6.6 连续第三声

- 字面拼音始终标词汇本调第三声。
- 即使朗读时前一个第三声实际接近第二声，也不写成第二声。
- 原因：三声变调受词组边界、停连和语流分组影响，不适合固化到逐字拼音。
- 朗读指导可另行记录停连或语流提示，但不得污染拼音字段。

### 6.7 轻声

轻声必须是词汇或教材确定的读法，不能仅凭“这个字经常作后缀”判断。

| 类型 | 示例 | 处理 |
|---|---|---|
| 现代词固定轻声 | 燕子、梅子、玻璃、衣裳（现代口语义） | 轻声音节不标调 |
| 独立名词或专名 | 童子、游子、稚子、子规、林子方 | 标本调 `zǐ` |
| 古诗韵脚或古义 | 上头、衣裳等 | 以教材随文读音为准，不能自动轻声化 |

同一个字在不同词中可以不同，禁止建立“子永远轻声”或“子永远三声”的全局规则。

### 6.8 儿化、语气词和叠词

- 儿化按规范词的一个音节处理，如连续拼写可写 `huār`。
- 当前逐字单元格模型遇到原文显式“儿”且读儿化时，不得擅自合并；应标记工具能力缺口并人工决定展示方式。
- 语气词“啊”等语流音变默认不改写字面拼音，除非教材明确随文标音。
- ABB、AABB 形式一般标本调；只有规范词实际固定读变调时才写变调。

### 6.9 规范异读和可接受变体

当权威辞书明确允许两个读音，例如某些语境中的 `shéi/shuí`：

- 不得把另一规范读音直接判为错误。
- 项目没有统一要求时保持原文档读音，状态标记 `KEEP_VARIANT`。
- 项目要求统一朗读口径时，可以统一，但错误类型应写“规范化统一”，不能写“错误读音”。

## 7. 工具选择和职责边界

### 7.1 Java 通用生成工具

使用：

```text
com.sp.selplat.common.tool.pinyin.PinyinDocxGenerationTool
```

工程编译版本为 Java 21。macOS 使用 Homebrew `openjdk@21` 时，应显式为 Gradle 设置 `JAVA_HOME` 和 `PATH`，不得因终端默认 Java 25 而改变工程目标版本：

```bash
JAVA_HOME=/opt/homebrew/opt/openjdk@21 \
PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH \
./gradlew :shared:backend:common-core:runPinyinDocxTool \
  -PpinyinSource="{source.docx}" \
  -PpinyinTarget="{target.docx}" \
  -PpinyinDictionary="{overrides.tsv}" \
  -PpinyinMode=paragraph \
  -PpinyinLayout=daodejing
```

`pinyinMode` 只允许 `paragraph`、`poetry` 或 `classical`；`pinyinLayout` 当前只允许 `daodejing`。参数名或取值错误时必须终止，不允许静默回退。

Gradle 任务已同时固定 `file.encoding`、`stdout.encoding` 和 `stderr.encoding` 为 UTF-8；中文路径、统计日志和错误信息不得因终端 `LC_ALL=C` 而变成问号。

职责：

- 读取 DOCX 原文。
- 调用第三方库生成候选。
- 使用专用 TSV 覆盖候选。
- 保证逐码点对齐。
- 按指定模式生成版式。

不负责：

- 自动证明读音正确。
- 自动解决所有古诗文异读。
- 把 TTS 结果当作规范读音。

### 7.2 第三方拼音库

`houbb:pinyin` 只承担初始候选生成。任何正式古文、专名或朗读版均必须经过候选检查和专用词典覆盖。

### 7.3 文档专用纠音词典

TSV 格式保持：

```text
# 注释
完整词组<TAB>逐字拼音，音节之间使用一个或多个空格
```

示例：

```text
春去花还在	chūn qù huā hái zài
不应人	bú yìng rén
长歌行	cháng gē xíng
```

规则：

1. 词组和拼音音节数必须按 Unicode 码点完全一致。
2. 词条尽量包含足够语境，避免错误覆盖同字的其他读音。
3. 不要把标点写进词条；当前解析器会把每个码点都计入音节数。
4. 单字词条只在该文档中所有出现位置都应同音时使用。
5. 同一文本需要两个不同读音时，扩大上下文词组；仍无法区分则不得强行写 TSV，必须升级为位置型覆盖。
6. 文件使用 UTF-8，拼音使用 NFC。
7. 每个正式词条必须在配套裁决记录中有来源。

### 7.4 定点修复工具

已生成且排版核定的 DOCX 只修少量拼音时，应使用满足以下条件的定点修复工具：

- 以“篇号/段号 + 完整上下文 + 汉字 + 当前拼音”定位。
- 只替换对应单元格拼音段的文本节点。
- 修改数量与清单数量不一致时失败。
- 先写同目录临时文件，ZIP 和 XML 校验成功后原子替换。
- 修改前保存哈希和临时回归副本。
- 修正后证明汉字序列、分页和非目标 OOXML 未变化。

`DaoDeJingPinyinRepairTool` 是特定历史文档工具，不得直接当作所有拼音 DOCX 的通用修复器。

### 7.5 文档视觉检查工具

统一使用 documents 技能中的 `render_docx.py`，由受管 Python 和 LibreOffice 运行时渲染全部页面。

检查用途：

- 页面数量。
- 拼音和汉字是否重叠或错位。
- 表格是否跨页拆分。
- 字体缺失、乱码和截断。
- 修改前后像素差异是否只出现在目标拼音附近。

### 7.6 禁止作为最终依据的工具

- 拼音库默认输出。
- 搜索引擎摘要。
- 普通拼音网站。
- TTS 或语音识别结果。
- 未注明教材版本的朗读视频。
- AI 自身记忆。

这些工具可以发现候选，但最终结论必须回到 L1 至 L5 证据。

### 7.7 教材汇总文档解析与分页

教材汇总 DOCX 必须先区分目录、分册、作品和正文，禁止把目录页码、超链接域或“课标必背/课后必背”标签输出到成品。

结构识别规则：

1. 分册范围必须覆盖任务实际年级；初中任务包括七至九年级，不得沿用只识别一至六年级的正则。
2. 标题、朝代和作者可能分段、同段、顺序互换或使用典籍来源；解析器必须把这些变体归一为标题、朝代、作者/来源三个字段。
3. “《孟子》三章”“《庄子》二则”“《礼记》二则”等容器标题只用于分组，不生成空白作品页；其子篇分别计数和分页。
4. 目录作品数是解析数量的验收基线。真实正文解析数与目录数不一致时必须停止，不得继续生成。
5. 原文缺少朝代或作者时，只能使用当前教材或正式典籍资料补全；无法核定时明确写“时代不详/佚名”，不得把标题人物猜成作者。

长篇分页规则：

1. `poetry` 表示每首诗词从新页开始，不等于每首必须压缩在一页；《木兰诗》、组诗序言和长篇歌行允许自然延续多页。
2. `classical` 表示每篇文言文从新页开始；篇内允许自然跨页，下一篇才插入硬分页。
3. 长篇跨页前必须先对完整自然段完成候选注音、朗读变调和专用词典覆盖，再按显示宽度拆行；禁止先拆显示行再纠音，避免词组、专名或“一、不”变调在行尾被截断。
4. 跨页只允许发生在完整的“拼音行 + 汉字行”组合之间；标题、朝代作者不得与正文首行分离，正文末页不得因固定页数目标产生异常大段空白。
3. 拼音候选、朗读变调和专用 TSV 必须在完整原句或原段上先执行，完成读音裁决后才允许按页面列宽拆成显示行。
4. 显示行优先在原文标点后换行，硬拆行不得删除、增加或移动任何原文码点。
5. 每个拼音/汉字上下双行单元必须设置不可跨页拆分，禁止页尾只留拼音或页首只留汉字。
6. 长篇续页不重复添加原文中不存在的标题、作者或“续”字样，除非用户明确要求。

验收时应分别记录：目录作品数、解析作品数、硬分页数、渲染总页数和发生自然跨页的作品。硬分页数应为作品数减一；渲染总页数可以大于作品数。

## 8. 标准作业流程

### 阶段 A：建立基线

1. 记录源文件和目标文件全路径。
2. 计算 SHA-256。
3. 记录页数、段落数、表格数、分页符数和汉字数。
4. 提取目录作品清单，并确认目录作品数等于正文解析作品数。
5. 提取标题、朝代、作者/来源、正文及当前拼音映射。
6. 备份只放临时目录，不在成品目录留下多余副本。

### 阶段 B：生成候选

1. 使用第三方库和已有 TSV 生成样稿或 dry-run 结果。
2. 枚举全部候选风险：
   - 多音字。
   - 姓名、地名、朝代作者和作品名。
   - 词牌、曲牌、典籍名。
   - 轻声音节。
   - 所有“一、不”。
   - 通假字、古义词和古今读音争议。
   - 生僻字及库回退到单字音的位置。
3. 相同汉字的不同拼音必须列出全部上下文对照。

### 阶段 C：证据裁决

每个候选至少记录：

```text
候选编号
文档位置
完整上下文
目标汉字
当前拼音
候选拼音
句义/词义
证据等级
来源名称
版本、页码或网址
裁决状态
```

裁决状态：

| 状态 | 含义 | 是否允许自动修改 |
|---|---|---:|
| `CONFIRMED` | 有直接权威证据且无冲突 | 是 |
| `RULE_DERIVED` | 在读音已确认后，由“一、不”等明确规则推导 | 是 |
| `KEEP_VARIANT` | 当前音属于规范异读，不判错 | 否 |
| `REVIEW_REQUIRED` | 权威来源冲突或证据不足 | 否 |
| `DRAFT_ONLY` | 只有征求意见稿支持 | 否 |
| `REJECTED` | 候选已确认不适用于该语境 | 否 |

### 阶段 D：先输出错误清单

正式修正前先生成 Markdown 清单，至少包含：

| 字段 | 说明 |
|---|---|
| 编号 | 稳定 ID，如 `A01/B01/C01` |
| 篇号/段号 | 可以唯一定位 |
| 标题 | 作品或段落名称 |
| 完整上下文 | 不能只写单字 |
| 当前拼音 | 修改前值 |
| 目标拼音 | 修改后值 |
| 错误类型 | 多音字、专名、轻声、一变调、不变调等 |
| 证据 | 等级、来源及直接支持内容 |
| 单元数 | 用于自动核对修改数量 |
| 状态 | 只允许 `CONFIRMED` 或 `RULE_DERIVED` 进入修改 |

清单还必须列出“明确保留项”，防止后续 AI 误改正确读音。

### 阶段 E：修正

1. 用户确认清单后再修改。
2. 原始未注音文档优先通过更新后的 TSV 重新生成。
3. 排版已经核定的成品优先使用定点修复。
4. 任一定位不唯一、当前拼音不匹配或总数不符时立即中止。
5. 不得为了达到预计数量而进行模糊替换。

### 阶段 F：自动验证

必须验证：

1. 清单目标全部命中。
2. 修改数量等于清单单元数总和。
3. 原文汉字和标点逐字一致。
4. 标题、作者、正文顺序一致。
5. 没有空拼音、非法音节、数字声调或非 NFC 拼音。
6. “一、不”全文统计符合预期。
7. 表格数、分页符数和页面数符合预期。
8. DOCX ZIP 完整性通过。
9. 再跑一次检查时应得到零个待修正项，即具备幂等性。

### 阶段 G：视觉验收

1. 渲染全部页面，不抽样替代全文渲染。
2. 检查每页标题、作者和正文是否可见。
3. 检查拼音是否位于对应汉字正上方。
4. 检查长拼音、带 `ü` 拼音和生僻字是否截断。
5. 对修改前后进行页面差异比较，变化应限制在目标拼音区域。
6. 最终成品如要求同时支持 WPS 和 Microsoft Word，应各打开一次进行人工抽查。

## 9. AI 判断与执行模板

后续 AI 执行拼音检查时使用以下模板，不得省略关键字段：

```text
任务：检查并修正拼音文档。

标引模式：READING_TEACHING
目标读者：儿童直接朗读
原文路径：{source_path}
当前拼音文档：{target_path}
专用词典：{dictionary_path}
版式参考：{reference_path_or_none}

强制要求：
1. 第三方拼音库、TTS 和搜索摘要只能作为候选，不能作为最终证据。
2. 按 L1→L6 来源等级核定多音字、轻声、专名和古诗文读音。
3. “一、不”按朗读实际变调标写；第三声变调仍标本调。
4. 先输出错误清单和明确保留项，未确认前不修改 DOCX。
5. 证据冲突或不足时标记 REVIEW_REQUIRED，不得猜测。
6. 修正时只改拼音层，不改原文和排版。
7. 修改后执行原文一致性、修改数量、结构、ZIP 和全文渲染检查。

每个结论必须输出：
位置 | 完整上下文 | 当前音 | 目标音 | 句义 | 证据等级 | 来源 | 状态
```

## 11. 自动检查清单

### 11.1 内容检查

- [ ] 原文 SHA-256 已记录。
- [ ] 汉字和标点序列与原文完全一致。
- [ ] 标题、朝代、作者和正文均已检查。
- [ ] 目录作品数与正文解析作品数一致，容器标题未被误计为作品。
- [ ] 每个汉字恰好一个拼音音节。
- [ ] 标点和空白没有拼音。

### 11.2 读音检查

- [ ] 所有多音字均结合完整语境复核。
- [ ] 所有人名、地名、词牌和典籍名均复核。
- [ ] 所有轻声音节均有词典或教材依据。
- [ ] 所有“一”均按语法作用和后续本调检查。

- [ ] 规范异读没有被误判为错误。
- [ ] 古音或押韵读法没有在无教材依据时擅自采用。

### 11.3 词典检查

- [ ] TSV 为 UTF-8。
- [ ] 每行恰好一个制表符分隔两列。
- [ ] 词组码点数等于拼音音节数。
- [ ] 没有重复词条。
- [ ] 长词优先不会被短词破坏。
- [ ] 每个词条都有裁决记录。
- [ ] 同文异音没有被全局词条错误覆盖。

### 11.4 DOCX 检查

- [ ] 源文件未修改。
- [ ] 目标 DOCX ZIP 完整。
- [ ] 修改数量与清单一致。
- [ ] 非目标拼音未变化。
- [ ] 定点修复任务的原文、表格、分页和版式未变化；重新生成任务符合已声明的分页版式基线。

- [ ] 全部页面已渲染检查。
- [ ] WPS 和 Word 兼容性按交付要求抽查。

## 12. 异常处理

| 异常 | 处理 |
|---|---|
| 找不到唯一上下文 | 中止，不做模糊替换 |
| 当前拼音与清单不一致 | 中止，重新生成基线清单 |
| 词组音节数不匹配 | 词典加载失败，不输出成品 |
| 同一词组需要不同读音 | 扩大上下文；仍冲突则升级位置型覆盖 |
| 权威来源冲突 | 标记 `REVIEW_REQUIRED`，请求人工核定 |
| 只有征求意见稿支持 | 标记 `DRAFT_ONLY`，不得修改 |
| 定点修复任务渲染页数变化 | 视为版式回归失败 |
| 重新生成任务页数大于作品数 | 检查是否来自长篇自然跨页；结构正确时允许，不得机械压回一页 |
| 低墨量扫描把篇末一两行判为空页 | 查看对应页面原图；有正文则记录为自然续页，真正纯白才判分页缺陷 |
| DOCX 打开失败或乱码 | 恢复临时副本，调查 OOXML/字体问题 |
| 旧 `.doc` 无法稳定解析 | 保留原文件，转换副本后再处理 |

## 13. 风险控制

### 13.1 第三方库升级风险

升级拼音库后默认词组结果可能变化。每次升级必须重新运行全文差异检查，不能直接覆盖核定版词典。

### 13.2 教材版本变化风险

统编教材修订可能调整正文、注释或读音。每次新任务应记录教材版次、年级、册次和页码，不能只写“人教版”。

### 13.3 规范更新风险

任务开始时必须重新查询国家标准状态和教育部正式发布信息。搜索结果中的发布日期、转载日期不能代替标准实施日期。

### 13.4 过度自动化风险

`一、不` 可以规则化，但必须在多音字和语法作用确认后执行。人名、地名、轻声和古诗文异读不能仅靠通用规则自动修正。

### 13.5 排版破坏风险

只修少量拼音时重建整份 DOCX 可能造成分页和字体变化。优先定点替换，并证明非目标 XML 未改变。

## 14. 验收标准

成品必须同时满足：

1. 标引模式已明确为 `READING_TEACHING` 或 `ORTHOGRAPHY`。
2. 每个改音项都有上下文和可追溯证据。
3. 只有 `CONFIRMED` 和 `RULE_DERIVED` 项目被自动修改。
4. `一、不` 符合所选模式，第三声变调保持本调。
5. 原文和标点逐字不变。
6. 修改数量与错误清单一致。
7. DOCX 结构完整并可打开。
8. 页面数量和版式符合任务基线；重新生成的长篇允许页数大于作品数。
9. 全文渲染检查无乱码、重叠、截断和错位。
10. 再次运行检查得到零个已确认错误。

未满足任一项时，不得称为“核定版”或“最终版”。
