# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. AI Desktop maintains one Developer renderer and must not add a second product variant without a new explicit product decision.

## Project data layout

- Keep AI Desktop-only main/preload/renderer protocols under `contracts/`. SELPLAT root `shared/` is reserved for capabilities or contracts with verified cross-application consumers; do not create an application-local `shared/` directory.
- Keep `apps/<manifest-name>/` limited to source, configuration, permanent test code, launchers, dependency manifests, and permanent scripts. Generated `node_modules`, runtime data, reports, and build artifacts are forbidden there.
- Resolve the real application name through `@selplat/node-common-core/path`. Put lock-specific dependencies and regenerable cache under `cache/<application>/`, compile/Sites/package output under `build/<application>/`, pending/running/disposable material under `OPTION/temp/<application>/`, and every terminal auditable record under `log/<application>/归档日志/`.
- Keep private user settings, authentication, active Harness sessions, and user-owned collaboration state in Electron `userData`; they are not project cache or project audit data.
- Treat the user-confirmed AI Memory SQLite location as one narrow exception to the general source/runtime split: `apps/ai-desktop/db/ai-memory-paths.json` is the only path authority and initially resolves the database to `/Users/showfolder/Documents/workSpace/SELF/SELPLAT/apps/ai-desktop/db/events.sqlite3`. Developer source launch and packaged Developer launch must resolve it through the same `AiMemoryPathResolver`; missing, malformed, relative, inaccessible or escaping configuration must block database initialization and must never fall back to `userData`, cache or another empty database. Track the configuration, README and SQL in Git, but precisely ignore only the active `events.sqlite3`, `events.sqlite3-wal` and `events.sqlite3-shm` files at the SELPLAT root.
- Keep the AI Memory persistence foundation inside Electron main-process `services/event-center/persistence/` and use Electron's built-in `node:sqlite` instead of a separately rebuilt native addon. `load-order.txt` is the only ordered SQL manifest; every published SQL file has one four-digit version and SHA-256 record in `AiDesktopSchemaVersion`, runs with its version insert in one immediate transaction, and becomes immutable after application. A private `userData/ai-memory-database-state.json` marker may record only initialization metadata and the configured-path hash: it never stores business data or acts as a database fallback. Only a genuinely first initialization may create the configured database; a missing initialized database, unknown existing database, corrupt marker, checksum mismatch, migration failure, or integrity failure disables database-backed business and exposes a path-free recovery status to the renderer. The renderer may read that status only and must never receive a SQLite connection or SQL execution method. Configure foreign keys, WAL, NORMAL synchronization and a 5000 ms busy timeout on open; checkpoint and close the one main-process connection during `before-quit`.
- Route every member, system, launcher and task event through the application-facing `EventCenterFacade`; keep `BusinessAuditLog`, JSONL, SQLite and Linghu consumption behind that facade. Cover early main-process startup, every IPC domain, renderer errors and unhandled rejections, background flows and shutdown without changing the original caller error. Persist workflow runs, task execution/heartbeats, evolution approvals, member runtime and application runtime sessions in the same main-process-only database without exposing SQL through IPC. Classify technical errors, business exceptions and stalled tasks separately, then move each exception through open, Linghu-owned processing and fact-backed resolved states. A 30-second supervisor independent of member tasks reconciles Nangong evolution, Han Li approvals, collaboration execution and Linghu state, detects expired task heartbeats once per fault fact, and gives Linghu the one unified exception queue. On startup, mark a previously running application session as interrupted and reopen abandoned processing items; normal shutdown stops the workflow session before checkpointing SQLite.
- An AI Desktop runtime-managed test batch starts at `执行日志/待执行/测试/<runId>/测试文档.<threadId>.md`, moves atomically as a whole to `执行日志/运行中/测试/<runId>/` while locked, and enters `归档日志/测试归档/<YYYY-MM>/<runId>/` on every terminal result. External SELPLAT engineering tasks keep their execution and test documents in the project-root `OPTION/` lifecycle managed by rule-engine. Preserve migrated history instead of deleting it.
