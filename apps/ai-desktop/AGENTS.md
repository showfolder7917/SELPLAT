# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Product-specific visual contract

- Use `ai-desktop` as the canonical application directory, package, runtime client, and rule scope name; use `AI Desktop` as the product identity.
- Keep Copilot wording only where the office variant intentionally reproduces the supplied visual reference or preserves a documented compatibility launcher; do not reuse it as the engineering project identity.
- Dismiss transient settings panels when the user clicks outside or presses Escape; interactions inside the panel must not dismiss it, and the behavior must not resolve or suppress approval dialogs.
- Keep workspace roots in an independently expandable multi-panel Accordion. Register real directories through the Electron main-process folder picker, persist them in local user data, default new roots to workspace-write, preserve later manual read-only choices, and map only explicitly writable registered roots into the official Codex turn sandbox policy.
- Keep the developer shell typography at desktop-IDE readability: primary navigation, workspace tree, controls, chat content, and context values should normally render at 13–15 CSS px with matching row height; do not use 10–11px for critical readable content.
- Keep the developer resource explorer, workspace, and tasks section headings as real disclosure controls with visible expanded state. Collapsing the resource explorer must remove the entire explorer grid column, expand chat and composer into the released width, and leave the activity-bar folder icon available to restore it. Place the new-task action at the right edge of the Tasks heading instead of rendering it as a separate full-width row.
- Keep both developer sidebar boundaries adjustable: the explorer's right edge changes its width, and the workspace/tasks divider changes their height allocation. Both separators must support pointer and keyboard operation; resetting returns the explorer to its standard width and lets the workspace fill all space above the Tasks heading by default. The workspace/tasks boundary must have one 5px hit area but draw only one 1px visual divider; nearby panel borders must not duplicate it.
- Write append-only business event timelines and per-task summaries under `apps/ai-desktop/log`. Each task summary must correlate the request, workspace/sandbox snapshot, Harness turn, approvals, commands, changed files, completion state, build freshness, and explicit partial-completion reason codes; never persist raw reasoning or authentication secrets. Expose the log directory and latest diagnosis in settings.
- Run managed work as an explicit four-stage state machine. `会话托管` is the default and only understands the user's intent. Its confirmation advances to read-only `需求托管`, which investigates causes and proposes a correction plan. Only the next confirmation opens `任务托管`, which must modify source, run static checks, launch one hidden isolated Electron, execute Playwright locator-based interaction tests, save screenshots only on failure under application temp, repair and retest for at most five validation rounds, close the isolated instance, and stop at code-level verification without a formal build or restart of the user's app. A final confirmation opens `测试托管`, which keeps the existing full build, post-build tests, repair loop, and at most one required restart. Conversation and requirement stages must reject file changes and privileged commands.
- Put an icon-and-text action at the lower right of each completed managed response: `就是这意思`, `按这个方案执行`, then `测试一下`. Clicking advances exactly one stage; a standalone `1` or the matching configured phrase has the same effect. After use, highlight the button and rename it to `重新分析需求`, `重新执行`, or `重新测试`; while running it is disabled and repeated use reruns only that target stage.
- Keep the official Harness approval policy at `on-request` with the user reviewer. For an eligible project command, the first `允许` action means `允许并信任`; persist only the exact real project root, cwd, command text, and package-script signature under Electron user data, then automatically answer later identical official approval requests. Any identity change, file-change request, destructive command, privilege/permission expansion, or Git-state destructive command must still require explicit review. Show the trusted count and a confirmed clear-all action in settings, and audit both trust creation and automatic allowance.
- Keep exactly one current AI Desktop-owned Harness thread with official persistent storage. Save only its active thread ID under Electron user data, resume it after renderer or Electron reconstruction, and keep using it when only the managed-stage sandbox changes. The explicit new-task action must call official `thread/delete`, clear the saved ID and local transcript, and start a fresh thread only on the next send; do not add an application history list. Put locale and natural collaborator-style guidance in `developerInstructions`; keep the first user message limited to registered workspace context, the real task, and attachments so internal templates cannot become repeated task titles.
- Render assistant replies as safe GitHub-flavored Markdown with readable headings, paragraphs, lists, quotes, code, links, and tables. Do not render raw HTML; route only validated HTTP(S) links through the Electron main process. Preserve user messages as plain text and keep Markdown typography legible in the dark developer theme.
- Keep the Windows developer launcher on the hot-development chain: Vite HMR updates React and CSS without restarting the app, while TypeScript watch plus the Electron process monitor restarts the Electron process when main, preload, or shared code changes. Keep formal build and static start commands separate and unchanged.
- When conversation management has ambiguity, surface the official Harness `requestUserInput` as one independent choice group per question, allow a free-form other answer, require every question before confirmation, and continue the same Harness turn. After answers, restate the complete intent before showing `就是这意思`.
- Preserve every assistant answer across managed rounds inside the same chat card. A new Harness turn appends a visibly separated text segment; its completed message may reconcile only that turn's segment and the final IPC response must never replace text accumulated from earlier rounds.
- Keep screenshot originals, annotations, metadata, and other disposable runtime files under `apps/ai-desktop/temp`; expose both “open temp directory” and confirmed “clear all temp files” controls, and send screenshots to the official harness only as main-process-resolved `localImage` attachments.
- Preserve the screen exactly as it looked when the screenshot button was clicked, then show only the screenshot selector and annotation layer in temporary full screen; completing or cancelling must restore the AI Desktop editor window to its original bounds and state.
- Keep a fixed `完成` action beside `取消` in the screenshot annotation footer. Completion without red annotations attaches the crop and focuses the chat composer without adding red-part copy; completion with annotations retains the existing red-part investigation prompt.
- Keep the developer chat history in a height-constrained independent scroll region with a visible vertical scrollbar; the composer stays fixed, and newly appended messages scroll into view without preventing the user from reviewing earlier content.
- Render Codex work from official app-server notifications as a real stream: append `item/agentMessage/delta`, show readable reasoning summaries, plans, command/file/tool lifecycle and changed-file updates, then reconcile with authoritative completed items. Keep the verbose execution-process list collapsed by default with a visible current-step summary. Never manufacture progress or expose raw reasoning text.
- Treat `OPTION/copilot/image.png`, `image1.png`, and `image3.png` as the source of truth for the desktop shell, chat states, and settings menu.
- Keep the main experience visually faithful to the supplied Microsoft 365 Copilot screenshots; do not expose Codex-specific labels in the chat chrome.
- Put locale switching, SELPLAT project selection, Codex connection details, and execution safety controls behind the lower-left settings gear.
- Support Japanese and Simplified Chinese without changing the core layout or control geometry.
- Do not present the binary publisher, signature, installer metadata, or About information as an official Microsoft product.
- Keep `启动办公版.bat` as the Windows office launcher and `启动办公版.command` as the macOS double-click office launcher; the macOS launcher must resolve the repository root from its own location and install missing desktop dependencies before starting.
