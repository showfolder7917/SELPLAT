# SELPLAT 公共前端共享与构建方案

## 1. 文档目的

本文用于确定 SELPLAT 各应用共享同一套主题、基础控件和前端素材时的代码归属、构建方式、发布方式与迁移顺序。

当前公共前端位于：

```text
apps/uniauth/backend/src/main/resources/static/sel/
```

该目录中的 `core`、`components`、`theme` 和 `assets` 不包含 Uniauth 业务语义，已经具备公共能力边界。因此，本方案不重新实现这些组件，而是调整其所有权并增加统一构建、发布能力。

## 2. 最终结论

采用以下组合方案：

1. 现有原生 JavaScript 组件继续作为公共组件的唯一底层实现。
2. 公共主题、组件和素材从 Uniauth 迁入 `shared/frontend/sel-ui`。
3. 使用 Vite 构建普通 JavaScript，不因构建需求强制引入 Vue。
4. 生产构建执行压缩、文件名 Hash，并关闭 Source Map。
5. 如确有提高阅读门槛的需求，可增加 JavaScript 混淆，但不得把混淆视为加密或安全边界。
6. `apps/host/backend` 作为 platform-runtime，通过统一端口发布 `/sel/**`。
7. Uniauth 和其他业务项目只保留自己的页面、布局样式和业务装配逻辑。
8. 将来业务页面统一使用 Vue 后，可以增加 Vue 薄适配层，但不复制现有组件实现。

## 3. 为什么不直接把公共前端改写成 Vue

Vue 与公共前端架构解决的问题不同：

- 公共前端架构解决资源归属、版本、构建和跨项目复用。
- Vue 解决页面状态管理、响应式渲染和组件组合。
- Vite 可以直接构建普通 JavaScript，使用 Vite 不要求使用 Vue。
- Vue 构建产物仍会被发送到浏览器，并不是真正加密。

如果现有 `selGrid`、`selTree`、`selWindow` 等组件已经满足业务需要，为了获得压缩产物而全部重写为 Vue，会增加迁移成本并产生两套实现。

因此当前以原生组件为本体；只有 Vue 页面确实需要声明式调用时，才增加适配器。

边界要求：

- `shared/frontend/sel-ui` 不得出现 Uniauth、MDA、CRM 等具体业务实体和接口地址。
- 公共组件只接收宿主节点、标准数据、选项和回调。
- 每个应用负责声明本应用 API、布局、数据映射和组件装配。
- 应用样式只负责页面布局及确有必要的业务展示，不复制公共组件内部样式。

## 5. 主题与组件的关系

公共目录包含的不只是主题，还包括基础运行时、控件和素材：

```text
/sel/core/**          公共运行时和请求工具
/sel/components/**    表格、树、窗口等基础控件
/sel/theme/**         主题契约、主题管理器和主题包
/sel/assets/**        背景、边框、光标等运行素材
```

所有组件统一读取 `--sel-theme-*` 自定义属性。切换主题时只改变主题状态和 Token，不复制组件 DOM，也不维护深色、浅色两套组件源码。

现有 `shared/frontend/theme/glass-theme` 应在后续审查其契约：

- 能适配当前 SEL Token 的，迁为 `sel-ui/src/theme/packs/glass-theme`。
- 不能适配的，先标记为旧预览资源，不能与 SEL 正式主题体系并行扩张。
- 一个正式页面只能使用一套主题契约，避免变量和组件样式相互覆盖。

## 6. Vite 构建职责

Vite 负责：

- 解析公共 JavaScript 入口和依赖关系。
- 合并并压缩 JavaScript、CSS。
- 删除生产构建中的注释和无用代码。
- 为产物生成内容 Hash 文件名。
- 将图片、字体等素材复制到构建目录并更新引用。
- 生产环境关闭 Source Map，避免直接暴露原始源码结构。

示意入口：

```javascript
// shared/frontend/sel-ui/src/index.js
import "./core/selBaseRuntime.js";
import "./core/selLocaleRuntime.js";
import "./core/selAjax.js";
import "./theme/runtime/selThemeRegistry.js";
import "./theme/packs/crystal-tech/manifest.js";
import "./theme/runtime/selThemeManager.js";
import "./components/grid/selGrid.js";
import "./components/tree/selTree.js";
```

生产配置原则：

```javascript
export default {
    build: {
        sourcemap: false,
        minify: true,
        manifest: true
    }
};
```

正式参数以实现时所选 Vite 版本的本地依赖和配置格式为准。构建产物必须进入模块 `build` 目录，不把临时 `dist`、日志或报告散落到源码目录。

## 7. 关于 JavaScript“加密”

前端 JavaScript 无法真正加密。浏览器要执行代码，就必须能够取得并解析代码。压缩和混淆只能提高阅读与逆向成本。

推荐保护级别：

| 目标 | 方案 |
|---|---|
| 避免直接阅读源码 | 压缩 JavaScript 和 CSS |
| 隐藏原始文件结构 | 合并模块并关闭生产 Source Map |
| 提高分析成本 | 可选 JavaScript 混淆 |
| 避免使用旧缓存 | 内容 Hash 文件名 |
| 降低资源篡改风险 | HTTPS、CSP，必要时增加 SRI |
| 真正保护敏感逻辑 | 将逻辑和密钥放在后端 |

以下内容禁止进入前端构建产物：

- 数据库账号和密码。
- JWT 或其他签名私钥。
- 第三方服务私钥。
- 服务端权限判定逻辑。
- 不允许用户获得的业务规则或算法参数。
- 可以绕过后端校验的状态和操作凭据。

混淆不能替代后端鉴权、参数校验和权限控制。

## 8. Gradle 与 platform-runtime 集成

公共前端建议注册为独立 Gradle 资源模块：

```gradle
// settings.gradle
include('shared:frontend:sel-ui')
```

构建后的浏览器资源进入 JAR 标准静态资源位置：

```text
META-INF/resources/sel/
```

platform-runtime 依赖公共前端资源模块：

```gradle
// apps/host/backend/build.gradle
implementation project(':shared:frontend:sel-ui')
```

运行时关系：

```text
shared/frontend/sel-ui 源码
        ↓ Vite 构建
带 Hash 的 JS、CSS、图片资源
        ↓ Gradle 资源 JAR
apps/host/backend
        ↓ platform-runtime 启动
http://localhost:8080/sel/**
```

公共资源只构建和发布一次。业务模块不能各自复制一份 `sel`，否则会出现版本不一致和修复遗漏。

如果某个业务应用仍需要脱离 host 独立启动，该应用可以依赖同一个 `shared:frontend:sel-ui` 资源模块，但仍不得复制源码。

## 9. 业务页面引用方式

公共资源使用以 `/sel/` 开头的绝对路径，避免页面层级变化导致 `../sel/` 失效。

开发期或兼容期示例：

```html
<link rel="stylesheet" href="/sel/core/selBaseReset.css">
<link rel="stylesheet" href="/sel/theme/contract/selThemeContract.css">
<link rel="stylesheet" href="/sel/theme/packs/crystal-tech/theme.css">
<link rel="stylesheet" href="/sel/components/grid/selGrid.css">

<script src="/sel/theme/runtime/selThemeRegistry.js"></script>
<script src="/sel/theme/packs/crystal-tech/manifest.js"></script>
<script src="/sel/theme/runtime/selThemeManager.js"></script>
<script src="/sel/components/grid/selGrid.js"></script>
```

完成统一打包后，页面应根据构建 manifest 引用带 Hash 的入口资源。业务应用自己的样式最后加载：

```html
<link rel="stylesheet" href="/uniauth/uniauth.css">
<script src="/uniauth/uniauth.js"></script>
```

加载顺序必须保持：

1. 基础 Reset 与无障碍样式。
2. 主题契约和主题包。
3. 公共组件样式。
4. 应用布局样式。
5. 公共运行时和公共组件脚本。
6. 应用装配脚本。

## 10. Vue 的可选适配层

如果未来新项目采用 Vue，可以增加：

```text
shared/frontend/sel-vue/
├── components/
├── composables/
└── plugin/
```

Vue 组件只负责：

- 把 Vue Props 转换为现有组件的标准输入。
- 在 `mounted` 阶段调用现有组件 `mount()`。
- 在 Props 变化时调用现有组件更新 API。
- 把现有组件回调转换为 Vue Emit。
- 在 `unmounted` 阶段调用 `destroy()` 释放监听器。

Vue 适配器不得重新实现表格、树、窗口的 DOM、样式和主题逻辑。现有 JavaScript 组件仍是唯一实现。

只有出现以下情况才创建 Vue 适配器：

- 新业务项目已经明确统一使用 Vue。
- Vue 页面频繁重复手动查找 DOM 和调用 `mount()`。
- 公共组件已经提供稳定的 `mount/update/destroy` 生命周期。
- 响应式数据更新或路由卸载确实需要 Vue 生命周期接管。

## 11. 主题选择的跨项目一致性

共享 `/sel/**` 可以保证所有项目使用同一套默认外观，但不能自动保证用户切换主题后跨项目保持一致。

当前主题管理器没有持久化时，刷新页面会恢复页面声明的默认主题。如果需要按用户保存，应由用户资料业务提供偏好接口，例如：

```text
GET /api/uniauth/users/me/preferences/theme
PUT /api/uniauth/users/me/preferences/theme
```

浏览器登录后通过 HTTP 读取偏好，再调用 `selThemeManager` 应用。后端保存稳定代码，例如：

```json
{
  "theme": "crystal-tech",
  "mode": "dark",
  "accent": "stellar-blue",
  "density": "comfortable"
}
```

主题包的展示名称可以国际化，但持久化值必须使用稳定代码，不能保存中文展示文本。

如果暂时只要求同一浏览器保存，也可以使用浏览器本地存储；但本地存储不能跨设备，清理浏览器数据后会丢失，不作为最终用户资料方案。

## 12. 迁移步骤

### 阶段一：建立公共模块

1. 建立 `shared/frontend/sel-ui` 和模块 README。
2. 登记 Gradle 模块和依赖关系。
3. 将 `uniauth/static/sel` 整体迁入公共模块。
4. 保留 `/sel/**` URL 不变，避免业务页面同步大改。
5. 验证公共代码中不存在 Uniauth 业务实体、接口或 mock 路径。

### 阶段二：接入统一运行宿主

1. platform-runtime 依赖 `shared:frontend:sel-ui`。
2. 验证 `/sel/**` 能由统一端口访问。
3. 将 Uniauth 页面引用从相对路径改为 `/sel/**` 绝对路径。
4. 验证 Uniauth 页面主题、表格、树、窗口和个性化功能。

### 阶段三：增加生产构建

1. 建立普通 JavaScript 的 Vite 入口。
2. 配置压缩、Hash 和关闭 Source Map。
3. 将构建产物接入 Gradle 资源处理流程。
4. platform-runtime 根据构建 manifest 发布或引用正式入口。
5. 验证离线构建、增量构建和缓存更新。

### 阶段四：其他项目接入

1. 新项目只引用 `/sel/**`，不复制公共资源。
2. 每个项目只建立自己的应用 HTML、CSS 和 JavaScript。
3. 项目需要的新通用控件先进入公共组件层，再由项目调用。
4. 项目特有控件留在项目目录，达到两个以上项目复用后再审查是否上移。

### 阶段五：按需增加 Vue 适配

1. 先选择一个新 Vue 页面试点。
2. 只包装实际需要的公共组件。
3. 补齐 `update` 和 `destroy` 生命周期后再扩大使用范围。
4. 不对现有原生页面执行一次性重写。

## 13. 验收标准

### 目录与依赖

- `apps/uniauth` 不再持有公共 `sel` 源码副本。
- 公共主题和组件只有 `shared/frontend/sel-ui` 一个源码来源。
- platform-runtime 能通过一个端口发布公共资源。
- 独立启动的业务应用按需依赖同一个公共资源模块。

### 功能

- Uniauth 页面迁移前后功能与视觉一致。
- 深色、浅色、Accent 和 Density 切换正常。
- 表格、树、下拉、日期、窗口和个性化控件正常工作。
- 图片、字体、光标和背景没有失效路径。
- 多实例组件状态互不污染。

### 构建与安全

- 生产 JS/CSS 已压缩。
- 生产文件名包含内容 Hash。
- 生产环境没有 Source Map 对外发布。
- 浏览器控制台没有 404、重复注册或加载顺序错误。
- 前端构建产物不包含密钥、数据库凭据和服务端权限逻辑。
- 混淆失败时不影响正常压缩构建，并且不能绕过功能测试。

### 兼容性与可访问性

- 键盘操作、焦点状态和语义元素保持有效。
- 主题切换后文字与背景对比度可用。
- 页面在常用桌面分辨率和缩放比例下没有结构破坏。
- 原生页面与未来 Vue 页面可以同时使用同一主题资源。
