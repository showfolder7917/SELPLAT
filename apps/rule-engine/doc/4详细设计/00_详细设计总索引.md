## 2. 设计原则

1. 所有路径、类和方法均为“计划新增对象”，不冒充现有实现。
2. memory 的 Python 常驻进程是唯一主动驱动端，拥有任务监听、Agent 启动、Codex 连接池、本地 Rule Factory、文件、测试、Gate Runner、审计事实和同步 outbox。
3. ai-factory 只登记角色/Agent/地址、提供 HTTP 校验与权威持久化、记录服务端 API 审计并提供只读工作流可视化；不主动调度 Agent 或执行本地任务。
4. Python 不直连服务端数据库；Java 不读取本地工作空间。
5. Java Controller 只解析/序列化 `CommonParam/CommonResult`，业务结构由 Service 产生。
6. 本地状态使用 Python 标准库 SQLite；HTTP 使用标准库 `urllib`，避免 MVP 新增第三方依赖。
7. 服务端 Java 工程结构参照 `apps/japanese`：`backend` 为实际构建，业务模块内分 `controller/service/service.impl/dao`。
8. 所有运行生成物统一进入 `OPTION/temp/ai-factory/任务/<task_id>/`；源码目录不接收任务文档、会话、Gate 证据或审计日志。
9. 业务资源允许 `RUL_中文`、`AGENT_中文`、`IDX_中文`；程序包、API、数据库字段和稳定 ID 保持英文。
10. 服务端 MVP 使用 H2 与 SELPLAT 公共数据库层；未来数据库替换不得改变 Service/API 合同。
