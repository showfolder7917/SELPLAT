# 架构脑与执行脑边界规范

版本：V1.0

## 1. 目标

明确 AI 系统中架构脑（Architecture Brain）与执行脑（Execution Brain）的职责边界，避免职责混乱、重复推理与决策失控。

---

## 2. 总体原则

### 架构脑

负责：

- 决定做什么
- 决定为什么做
- 决定如何做

输出：

- Requirement.md
- Design.md
- Rule.md
- Gate.md
- Process.md

不直接修改代码。

### 执行脑

负责：

- 根据设计实施
- 修改代码
- 测试验证
- 缺陷修复

输出：

- 代码变更
- 测试报告
- 修复报告
- Review报告

不负责制定规则及流程。

---

## 3. 边界定义

### 架构脑输入

- 用户需求
- 测试总结
- 门禁失败记录
- 审计记录
- 历史经验库

### 架构脑输出

- Requirement.md
- Design.md
- Rule.md
- Gate.md
- Process.md

### 架构脑权限

允许：

- 新增规则
- 修改规则
- 新增门禁
- 修改流程
- 调整Agent职责

禁止：

- 修改业务代码
- 提交代码
- 发布系统

---

### 执行脑输入

- Requirement.md
- Design.md
- Rule Library
- Task List

### 执行脑输出

- 代码修改
- 测试报告
- 修复报告
- Review报告

### 执行脑权限

允许：

- 修改代码
- 运行测试
- 修复Bug
- 输出测试报告

禁止：

- 修改规则
- 修改门禁
- 修改流程
- 重新定义需求
- 修改设计

---

## 4. 问题归属规则

### A类 实现问题

例如：

- 代码报错
- SQL错误
- 测试失败
- 接口异常

归属：执行脑

### B类 设计问题

例如：

- 设计遗漏
- 边界条件缺失
- 接口定义错误
- 模块划分不合理

归属：架构脑

### C类 流程问题

例如：

- 同类问题反复发生
- Rule失效
- Gate漏检
- Agent职责冲突

归属：架构脑

---

## 5. 升级原则

第一次出现：

测试失败 → 执行脑修复

第二次出现：

测试失败 → 修复 → 记录经验

第三次出现：

视为流程缺陷，升级至架构脑分析。

分析内容：

- 是否新增Rule
- 是否新增Gate
- 是否调整流程

---

## 6. Rule与Gate职责

### Rule

作用：告诉Agent应该怎么做。

例如：

R001：设计必须指定文件、函数、验收标准。

### Gate

作用：验证Rule是否被遵守。

例如：

G001：检查是否存在文件、函数与验收标准。

### 核心原则

Rule负责预防。

Gate负责执法。

## 9. 决策矩阵

- 用户提出需求：架构脑
- 编写需求文档：架构脑
- 编写设计文档：架构脑
- 修改代码：执行脑
- 执行测试：执行脑
- 修复Bug：执行脑
- 新增规则：架构脑
- 新增门禁：架构脑
- 调整流程：架构脑
- 生成测试报告：执行脑
- 发布审批：架构脑
- 审计记录：双方

---

## 10. 企业级建议

Rule Library：目标50条，警戒100条，硬上限200条。

Gate Library：允许持续扩展。

遵循原则：

简单规则 + 严格门禁 + 失败反馈 + 持续进化。
