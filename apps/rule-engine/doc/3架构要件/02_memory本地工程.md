# 分包 02：memory 本地工程架构要件

## 1. 工程定位

`apps/ai-memory` 是本地 Python AI 工厂。它不是全局 Memory Library，而是用户侧的需求分析、Agent 编排和执行工作台。它负责产生本地文件与实际执行事实，但不拥有服务端业务状态和正式治理版本。

## 2. 建议组件

| 组件 ID | 组件 | 职责 |
| --- | --- | --- |
| CMP-MEM-001 | 本地启动入口 | 解析本地身份、工程、角色入口和服务配置 |
| CMP-MEM-002 | 需求与架构工作台 | 需求澄清、要件/架构/设计文档生成与本地草稿 |
| CMP-MEM-003 | Agent Runtime | 固定角色、上下文、权限和阶段运行，启动 Codex |
| CMP-MEM-004 | Workspace Manager | 本地工作空间、Git、锁、原子文件和产物摘要 |
| CMP-MEM-005 | Test/Fix Runner | 命令、测试、证据、诊断和受控修复 |
| CMP-MEM-006 | Local Rule Factory | Rule/Gate/Process 提案、索引、依赖/冲突检查、规则包构建与批准快照仓 |
| CMP-MEM-007 | Sync Outbox | 幂等上报进度、产物、错误、审计和完成事实 |
| CMP-MEM-008 | Local Gate Runner | 在只读受检快照上执行文件、源码、测试和本地环境 Gate |

| ARC ID | 来源要件 | 组件 | 架构约束 | 验收方式 |

| ARC-MEM-002 | REQ-REQ-005～REQ-REQ-009 | CMP-MEM-002/007 | 要件必须使用稳定 ID 和完整字段，本地解析后连同文件摘要上报服务端，由服务端 Gate 决定状态。 | 要件对账测试。 |

## 4. 本地数据边界

本地可保存：工作空间文件、Git 元数据、Rule/Gate/Process 源文件与候选包、已批准固定快照、待上报 outbox、命令输出、测试证据和恢复点。不得自行认定为权威事实：批准状态、服务端聚合 Gate 结果、正式发布状态或跨用户集中数据。

## 5. 故障原则

- 无服务连接：允许编辑本地草稿；禁止创建正式阶段和宣称批准。
- 已领取执行中断网：只在租约、包和策略允许的窗口内继续安全本地动作，所有外部副作用默认暂停。
- 重连：先校验任务、租约、包版本和摘要，再按幂等顺序补报。
