# 分包 12：部署、恢复与非功能架构要件

## 1. 部署模型

- memory：用户本机 Python 进程，可按需求启动；访问本地文件、Git、Codex、测试工具和本地 Rule Factory。
- ai-factory：未来服务器长期运行的 Java HTTP 服务，连接权威数据库并提供 API、SSE、治理包审批登记、Gate 结果聚合和管理页面；不运行 Rule Factory。
- 两者独立构建、发布、配置和升级，通过兼容 API 版本协作。

## 3. 发布兼容

memory 与服务端版本必须通过兼容矩阵协商。服务端 API 返回支持版本和弃用时间；memory 不支持当前主版本时必须阻断正式运行，但可继续编辑本地草稿。

## 4. 可用性原则

MVP 不承诺服务端高可用集群，但架构不得阻止未来横向扩展。无论单实例还是集群，工作流状态、租约和幂等均以共享权威数据库为准。
