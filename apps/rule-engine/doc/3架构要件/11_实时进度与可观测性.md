# 分包 11：实时进度与可观测性架构要件

## 1. 目标

本分包定义 memory 的执行事件与 ai-factory 的持久化进度、心跳、STALE 检测、SSE 页面、查询和质量指标。

## 2. 事件族

| 事件 ID | 事件 |
| --- | --- |
| EVT-RUN-001 | stage.claimed / started / heartbeat / stale / completed |
| EVT-ART-001 | artifact.created / changed / uploaded / gated |
| EVT-TST-001 | test.started / passed / failed / evidence.ready |
| EVT-GAT-001 | gate.started / passed / failed / invalidated |
| EVT-ERR-001 | error.recorded / correction.attempted / regate.requested |
| EVT-WFL-001 | state.transitioned / blocked / approval.requested |

## 3. 架构要件

| ARC ID | 来源要件 | 架构约束 | 验收方式 |
| --- | --- | --- | --- |
| ARC-OBS-001 | REQ-RUN-002、REQ-NFR-005 | 服务端页面/API 必须按根任务展示阶段、角色、Thread、Agent、心跳、动作、文件、测试、Gate、错误、预算和阻断。 | UI 数据覆盖 Gate。 |
| ARC-OBS-002 | REQ-RUN-007 | memory 在领取、加载、启动、生成、测试、修复和结束时发送结构化事件和心跳。 | 长任务事件测试。 |
| ARC-OBS-003 | REQ-RUN-008 | 服务端基于租约和心跳阈值标记 STALE，并路由重试、终止或人工核对。 | 心跳丢失测试。 |
| ARC-OBS-004 | REQ-RUN-009 | progress_event 在服务端持久化且有根任务内单调序号；百分比只用于展示。 | 乱序和 100% 伪完成测试。 |
| ARC-OBS-005 | REQ-RUN-010 | 页面加载先取数据库快照，再用 Last-Event-ID 订阅 SSE；重复事件由序号去重。 | 刷新/断线测试。 |
| ARC-OBS-006 | REQ-RUN-011 | 错误事件包含 error_id、任务/运行/角色、时间、类型、退出码、摘要、脱敏堆栈、尝试和证据引用。 | 错误 Schema Gate。 |
| ARC-OBS-007 | REQ-RUN-012 | Worker 完成事件只表示事实提交完成，页面显示“等待 Gate”而非直接完成。 | 状态展示测试。 |
| ARC-OBS-008 | REQ-AUD-012 | 查询 API 支持 task_id/root_thread_id，并返回完整因果链和权限过滤结果。 | 查询测试。 |
| ARC-OBS-009 | REQ-EVO-012 | 服务端从事实事件计算覆盖率、Bug、重复问题、Gate 失败和发布结果趋势。 | 指标可重建测试。 |
| ARC-OBS-010 | REQ-NFR-001、REQ-NFR-014 | 两端记录阶段耗时、网络等待、模型/工具资源和成本，区分本地与服务端耗时。 | 性能成本报表测试。 |
| ARC-OBS-011 | REQ-NFR-003 | 页面重启不丢状态；服务端重启从数据库恢复事件游标和 STALE 检测。 | 重启恢复测试。 |
| ARC-OBS-012 | REQ-NFR-007 | 新事件类型必须注册 Schema 和兼容策略，未知可选事件不使旧客户端崩溃。 | 兼容性测试。 |

## 4. 告警边界

必须至少告警：长期无心跳、审计写失败、Gate Runner 故障、outbox 长期积压、摘要冲突、修复超限、敏感信息违规和备份校验失败。

## 5. 管理页面部署

管理页面属于 ai-factory 服务端，可使用 SelUI 并通过同源 API/SSE 访问。memory 可提供本地简化状态视图，但不得成为权威状态来源。
