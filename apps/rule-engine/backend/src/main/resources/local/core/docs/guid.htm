rule-engine 本地分层结构与阅读链路

本页说明迁移完成后的 core、common、用户层结构，以及启动协议、规则索引和能力代码的唯一读取入口。

现在的结构

  • resources/local/core/ 保存只读核心协议、规则、注册表、文档和人工资料。
  • resources/local/common/ 保存经人工审查合并的公共规则资源。
  • resources/local/<user>/ 保存用户后续修正；生产冲突优先级为用户、common、core。

链路开始端

  1. 重开会话后，从 resources/local/core/protocol/STARTER_PROTOCOL.md 进入固定启动链
  2. 专项规则只通过根 RULE_INDEX.md 命中后按需加载
开始端 = resources/local/core/protocol/STARTER_PROTOCOL.md

目录总览

resources/local 规则资源分为不可自动修改的 core、人工维护的 common 和相互隔离的用户层。

core

初始基线层。承接启动协议、基础规则、注册表和迁入资料；迁移冻结后自动化程序不得新增、删除或修改。

protocol/ 协议层。`STARTER_PROTOCOL.md` 是唯一最小启动入口；规则按需通过 `RULE_INDEX.md` 进入，不在启动链默认展开。
rule/ 正式规则层。当前以扁平规则文件为主，专项协议默认对应同主题规则文件。
code/ 运行与编码层。这里同时承接运行能力库入口，以及 Python、JS、Java 的专题协议/规则/经验所对应的代码运行目录。

common 与用户层

common 是原规则引擎及人工审查后的共享层；XUNAN、TongXiaoFeng 等用户层保存各自后续修正。

common/ 仅允许人工审查并手工合并，自动化程序不得把用户修正直接写入 common。
<user>/ 用户独立根目录；自动修正规则与代码只写入已验证的当前用户层。
加载顺序 core → common → 当前用户；后加载覆盖前层。
人工合并 用户层候选变更经人工审查后，才可手工合入 common。
语言目录 Java、Python、Node 各自在语言原生 source set 下使用相同的 core/common/用户分层。
规则入口 所有规则只通过 resources 根 RULE_INDEX.md 定位，不从旧记忆目录反推。

阅读链路

1
重开会话先读 protocol 先读 resources/local/core/protocol/STARTER_PROTOCOL.md，确认当前启动规则和最小读取链路。
2
按需读其他协议 从 resources 根 RULE_INDEX.md 中按任务类型选择规则，不默认全量展开。
3
再从协议进入 rule 如果任务涉及执行口径、分层写入、协作风格或提示词规范，再按根索引读取对应层的具体规则。
4
最后按需进入 experience 如果需要更细的历史判断依据，优先回到同主题规则或代码上下文，不再保留独立经验目录。
5
按任务类型进入 code Code 层同时承接运行入口与专题编码入口；运行任务读 RUNTIME_ENTRY.md，专题任务按主题进入对应协议、规则、经验。

重开会话后先读什么

  1. resources/local/core/protocol/STARTER_PROTOCOL.md
默认不再要求一上来全量展开多个规则文件，直接从单一启动入口进入。

AI 区边界

  • local/core/ 只保留迁入的核心知识、协议、规则、注册表和必要模板。
  • 迁移冻结后 core 不接受自动修正。
  • 后续修正先进入当前用户层，公共化必须人工合入 common。

什么时候读 rule

  • 要确认回答风格、协作口径时：读 local/core/protocol/USER.PROTOCOL.md
  • 要确认执行方式、索引同步、命令口径时：读 local/core/rule/PROJECT_EXECUTION_RULES.md 与 local/core/protocol/COMMAND.PROTOCOL.md
  • 要确认分层文件改写边界时：读 local/core/rule/MEMORY_FILE_EDIT_RULES.md
  • 要执行 GUI 或视频任务时：读 local/core/rule/GUI_VIDEO_TASK_RULES.md
  • 要执行 Code 运行相关任务时：读 local/core/protocol/CODE.PROTOCOL.md
规则层按协议同主题文件直接定位

什么时候读 experience

  • 当前结构已取消独立经验目录。
  • 已有经验判断应直接回到同主题规则、协议或代码上下文中处理。
  • 这类材料不再作为单独一层入口存在。
经验判断回收到规则层和代码上下文，不再通过独立 experience 目录定位

什么时候读 code

  • 运行任务：读 resources/local/core/docs/code/RUNTIME_ENTRY.md
  • Python 主题：CODE_PYTHON_RULES.md / PYTHON_EXPERIENCE.md
  • JS 主题：CODE_JS_RULES.md / JS_EXPERIENCE.md
  • Java 主题：CODE_JAVA_RULES.md / JAVA_EXPERIENCE.md
统一入口：resources/local/core/docs/code/RUNTIME_ENTRY.md

什么时候读 code 运行层

  • Code 运行任务优先走 ability，不直接走 skill
  • abilities/ 是 AI 可调用入口
  • skill/ 和 app/ 是内部依赖
  • registry/ 负责机器索引，执行约束已并入 CODE.PROTOCOL.md
统一入口：resources/local/core/docs/code/RUNTIME_ENTRY.md

人类该看哪几个入口

  • 总览结构：README.md、RULE_INDEX.md
  • 看目录导航：Home.md
  • 看可视化结构和阅读链路：当前这份 guid.htm

  • 默认先读 STARTER_PROTOCOL.md
  • 其余目录按任务需要再补读，不需要每次全量展开
