# 详细设计模板目录

- 本目录用于存放“正式可复用”的详细设计模板资产
- 当前批处理详细设计默认模板文件：
  - `详细设计模板_批处理业务功能处理详细.xlsx`
- 当前页面调用详细设计默认模板文件：
  - `详细设计模板_页面调用处理详细.xlsx`
- 该模板按日本式详细设计书 / 处理详细的骨架设计，作用是复用页头、表格结构和处理详细排版，不是固定业务页签数量
- 正式生成时必须先判断类型：
  - 批处理：可以使用 `主处理` 作为批处理框架入口，再按内部方法拆页
  - API / 页面调用：可以使用 `01_主处理` 作为 API 框架入口，但必须配套 `IFxx_接口名_接口项目`、`02_错误时处理`、`Lxx_内部方法` 页签
  - 单纯页面事件：不得伪装成批处理主处理；应在 Lxx 页面方法页中写点击、状态、跳转和桥接
- API / 页面调用链必须显式展现页面、前端事件、前端 API、后端 Controller、Service、DAO、Domain、数据库表/SQL 的职责边界，不得用一个“服务端”概括 Java 端
- 正式生成时必须按业务功能、接口契约、入口处理、错误处理和内部方法动态扩展 sheet，并让方法一览与详细页一一对应
- 推荐命名方式：
  - `功能构成_功能名`
  - `IF01_接口名_接口项目`
  - `IF02_接口名_接口项目`
  - `01_主处理`
  - `02_错误时处理`
  - `L01_方法名（页面事件）`
  - `L02_方法名（前端API）`
  - `L03_方法名（Service）`
  - `L04_方法名（DAO）`
- 工作簿内容必须统一使用中文；只有源码标识符、URL、SQLID、类名、方法名允许保留原文
- 每个方法或事件页都必须包含：
  - `方法定义`
  - `参数`
  - `返回值`
  - `处理详细`
- `处理详细` 必须写到可对应代码实现的粒度，至少覆盖：
  - 主步骤与子步骤
  - 分支条件与结束路径
  - 循环条件与循环体
  - 内部方法调用块
  - 共通部品 / 业务部品 / DAO / SQL 调用块
  - 参数、返回值、设置值、备注
- `处理详细` 的编号步骤必须直接带中文说明，不能只有 `1.`、`2.`、`3.`：
  - 正确：`1. Controller 接收查询黑板入口请求，并绑定路径参数 coursewareId。`
  - 错误：只显示 `1.` 后面跟一个表格
  - 步骤说明行必须横向合并或使用足够宽的可读区域，不能写入窄列导致视觉上只剩编号
- 接口项目规格页必须逐字段写明：
  - 字段名、字段中文名、层级、重复、类型、长度、必填
  - 请求 / 返回方向
  - 来源 / 设置值
  - 备注和详细说明
- API / 页面调用详细设计的推荐页签组：
  - `功能构成_功能名`
  - `IFxx_接口名_接口项目`
  - `01_主处理`
  - `02_错误时处理`
  - `Lxx_内部方法（页面事件 / 前端API / Controller+Service / DAO / Domain）`
- 不得机械生成 `*_Controller`、`*_Service`、`*_DAO`、`*_Domain` 等大量薄页；如果单层逻辑很少，应在对应 Lxx 方法页的调用块和字段映射表中体现分层，避免空 sheet 和耦合误导
- 表格必须按步骤语义动态生成：
  - 方法调用、接口调用、DAO/SQL 调用：生成调用块
  - 对象组装、字段设值、状态回填、响应映射：生成字段映射表
  - 仅说明性步骤、分支结束、continue / break / return：没有结构化字段动作时不生成空表
- 表格生成时必须保留参考件的横向合并区块布局：
  - 不能把调用块拆成单列竖排标签
  - 不能把字段映射表缩成几列散点
  - 必须沿用参考件那种横向区块、合并跨度和阅读节奏
- `功能构成` 页也必须按横向合并表格重画：
  - `接口／入输出` 的输入类别、ID、名称、备注必须是横向表格
  - `方法一览` 的 No.、页签名、方法名、层、说明必须是横向表格
  - 禁止把页签名、ID、说明写在窄列里造成竖排碎字
- 正式生成后必须把所有 sheet 的视图恢复为 `normal`，并清除参考件残留的 pageBreakPreview / 无效分页线，避免打开时显示空白分页区域
- 正式生成后必须清除冻结窗格、pane、topLeftCell、selection 等旧视窗状态，所有 sheet 打开时必须定位在 `A1`
- 颜色模块必须按参考件语义使用：
  - 深蓝：文档页头、系统名、子系统名、功能名、版本、日期等文档元数据
  - 浅蓝：方法定义、接口输入输出、字段映射、业务固有对象、DAO/DB/SQL、Domain 对象和数据表相关块
  - 绿色：业务共通部品、跨层业务调用、Controller 调 Service、Service 调业务共通能力等业务调用块
  - 黄色：系统共通部品、框架、浏览器 API、日志、异常、URL/window/fetch 等系统或平台共通能力
- 清理或重画内容区后，必须先按参考样例重建 merged ranges 和横向区块骨架，再写入内容；不能只清边框后直接往普通单元格里填值
- 正式生成后必须做版式回归校验：
  - 校验关键调用块和字段映射表的 merged ranges 已按参考跨度恢复
  - 校验不存在“有边框或底色但整行无值”的空表残留
  - 校验未出现单格竖排标签、单列字符堆叠或未合并散点回退
- 正式生成工作簿时，必须先清除模板页中未使用的占位表格样式，再按实际步骤插入需要的表格
- 若逻辑复杂，必须继续按页面事件、前端 API、Controller、Service、DAO、Domain 拆出多个 Lxx 方法 sheet，不得把多个复杂方法堆在一个 sheet
- 页面方法页重点写点击、状态同步、跳转、URL 参数桥接；前端 API 方法页重点写 request/fetch 封装；接口项目页重点写字段 contract；Controller/Service 方法页重点写路由、响应封装、业务判断和事务；DAO 方法页重点写 SQL 与表；Domain 字段映射重点写字段语义和层间承载，以控制耦合
- 当前表结构定义默认模板文件：
  - `表结构定义模板_通用.xlsx`
- 后续若任务要求“继续生成批处理详细设计 Excel”但未显式指定模板路径，应优先使用 `详细设计模板_批处理业务功能处理详细.xlsx`
- 后续若任务要求“继续生成页面调用、前端到后端、接口到数据库链路详细设计 Excel”但未显式指定模板路径，应优先使用 `详细设计模板_页面调用处理详细.xlsx`
- 后续若任务要求“继续生成表结构定义书 Excel”但未显式指定模板路径，也应优先从本目录查找默认模板
- 若新增其他详细设计模板，应保持命名清晰，并同步更新对应规则与能力回路
