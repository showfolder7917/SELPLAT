# 模块系统修正索引

本文件用于约束 `apps/<module>` 一类模块工程发生变更后，AI 必须同步检查和修正的文件范围。

## 1. 触发动作：新增模块工程

必须同步修正的文件：

- 新模块自身 `README.md`
- 新模块自身 `manifest`
- `apps/README.md`
- 平台根 `README.md`
- `package-meta/modules/<module>.json`
- `package-meta/modules/README.md`
- `package-meta/dependency-map/modules.json`
- 若属于架构层新增能力，则补充 `docs/architecture` 对应蓝图

可选同步检查文件：

- 宿主模块的装配说明
- 若模块默认启用，则同步 `package-meta/profiles` 中对应启用清单
- 是否需要新增模块级静态预览或占位入口

需要避免的旧描述：

- 模块目录已创建，但平台文档仍没有该模块
- 模块已接入，但宿主说明里未体现

## 2. 触发动作：删除模块工程

必须同步修正的文件：

- `apps/README.md`
- 平台根 `README.md`
- 被删除模块自身的入口说明
- 如该模块出现在架构文档中，则同步更新相关架构文档

可选同步检查文件：

- 宿主注册表或模块发现入口
- 启动说明是否仍引用该模块

需要避免的旧描述：

- 目录已删，但平台说明和装配文档仍保留旧模块

## 3. 触发动作：模块改名

必须同步修正的文件：

- 旧模块与新模块的 `manifest`
- `apps/README.md`
- 平台根 `README.md`
- 宿主装配说明
- 涉及该模块的架构文档

可选同步检查文件：

- 预览入口或测试入口里是否仍有旧模块路径
- 若模块名暴露在文档标题中，也应同步更新

需要避免的旧描述：

- 目录名已经更换，但 manifest、README、架构文档仍混用新旧名称

## 4. 触发动作：宿主与模块装配关系变化

必须同步修正的文件：

- 宿主模块说明文档
- 模块自身 `manifest`
- 平台启动说明
- 若属于架构边界变化，则补充或更新 `docs/architecture` 文档

可选同步检查文件：

- 是否需要在 `ai-standards/索引.md` 中补充新的修正规则入口

需要避免的旧描述：

- 模块接入方式已经改变，但宿主说明仍按旧装配模型描述
