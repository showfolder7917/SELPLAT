# 安装版缓存目录统一规范

## 1. 目的与适用范围

本规范定义 SELPLAT 桌面应用在开发运行、安装运行和免安装压缩包运行时，程序文件、配置、缓存、日志、会话、诊断及 AI 生成文件的统一归属。

适用于：

- Windows 安装版和免安装压缩包版。
- macOS `.app`、DMG 安装版和解压运行版。
- Linux 桌面安装版和解压运行版。
- Electron、Node 或其他需要在用户机器持续保存运行数据的 SELPLAT 应用。

本规范不替代《工程临时目录规范》。目录分流由应用版本决定：开发版无论是否打包都遵守《工程临时目录规范》，发布版遵守本文的平台用户目录规范。

## 2. 核心原则

1. 安装目录只保存不可变程序文件，不保存会持续变化的运行数据。
2. 发布包不得依赖、内置或推断开发机工程绝对路径。
3. 配置、会话、日志、诊断、生成文件和缓存必须按语义分开。
4. 缓存必须可删除并可重新生成；日志、会话和用户生成文件不得按缓存清理。
5. 应用移动、升级或重新安装后，用户数据和日志仍能被稳定定位。
6. AI 必须通过运行路径清单或应用接口定位日志，禁止扫描用户磁盘猜测目录。
7. 密钥、令牌和密码进入操作系统凭据设施，不得以明文写入配置、日志或路径清单。
8. “开发版/发布版”是路径分流的唯一业务条件，不得根据是否安装、是否压缩包或可执行文件所在位置猜测。

## 3. 稳定标识

每个应用必须登记稳定的 `<applicationId>`，只允许 ASCII 字母、数字、短横线和下划线。显示名称变化不得改变 `<applicationId>`。

示例：

```text
applicationId = ai-desktop
vendorId = SELPLAT
```

目录解析必须使用稳定标识，不得根据窗口标题、安装包文件名、用户输入或当前进程所在目录临时生成应用目录名。

## 4. 安装目录边界

安装目录或压缩包解压目录只允许包含：

- 可执行程序及运行时。
- 已编译的页面、主进程和预加载资源。
- 应用图标、语言包及只读静态资源。
- 锁定并经过安装包门禁的生产依赖。
- 启动入口和只读版本信息。

禁止写入安装目录：

- 日志、崩溃转储和运行诊断。
- 用户配置、会话和 AI 任务状态。
- 下载、转换、浏览器、模型或依赖缓存。
- AI 生成文件、截图和导出临时副本。
- 数据库运行文件和待迁移数据。

开发压缩包版和发布压缩包版都遵守安装目录只读边界。开发压缩包版把运行数据写入明确的 `SELPLAT_ROOT`；发布压缩包版写入平台标准用户目录。“免安装”只表示不需要安装程序，不表示运行数据必须写在解压目录旁边。

## 5. 发布版平台默认目录

本章只适用于发布版。开发版不得因为被打包为 EXE、`.app` 或 ZIP 而切换到本章目录。

### 5.1 Windows

```text
%LOCALAPPDATA%\SELPLAT\<applicationId>\
├─ config\
├─ sessions\
├─ generated\
├─ diagnostics\
├─ logs\
│  ├─ current\
│  └─ archive\<YYYY-MM>\
├─ cache\
└─ runtime-paths.json
```

Windows 默认运行数据根为：

```text
%LOCALAPPDATA%\SELPLAT\<applicationId>
```

不得默认写入 `C:\opt\workspace`、安装目录、当前工作目录、桌面或下载目录。

### 5.2 macOS

持久数据：

```text
~/Library/Application Support/SELPLAT/<applicationId>/
├─ config/
├─ sessions/
├─ generated/
├─ diagnostics/
└─ runtime-paths.json
```

日志：

```text
~/Library/Logs/SELPLAT/<applicationId>/
├─ current/
└─ archive/<YYYY-MM>/
```

缓存：

```text
~/Library/Caches/SELPLAT/<applicationId>/
```

不得把运行数据写入 `/Applications/<application>.app`、`.app/Contents/Resources` 或 DMG 挂载目录。

### 5.3 Linux

遵守 XDG Base Directory：

```text
dataRoot   = ${XDG_DATA_HOME:-~/.local/share}/selplat/<applicationId>
configRoot = ${XDG_CONFIG_HOME:-~/.config}/selplat/<applicationId>
cacheRoot  = ${XDG_CACHE_HOME:-~/.cache}/selplat/<applicationId>
logRoot    = ${XDG_STATE_HOME:-~/.local/state}/selplat/<applicationId>/logs
```

未设置 XDG 变量时必须使用上述默认值，禁止回退到安装目录。

## 6. 数据分类

| 分类 | 目录 | 生命周期 | 是否允许自动清理 |
|---|---|---|---|
| 应用配置 | `config` | 跨版本保留 | 否 |
| AI 会话和任务恢复点 | `sessions` | 跨启动保留 | 仅按明确策略归档或清理 |
| AI 自动生成文件 | `generated` | 用户资产 | 否 |
| 运行诊断和崩溃信息 | `diagnostics` | 按保留策略归档 | 是，但必须保留未处理故障证据 |
| 当前日志 | `logs/current` | 当前运行或当前轮转周期 | 轮转后清理 |
| 归档日志 | `logs/archive` | 按月份保存 | 按保留策略清理 |
| 可重建缓存 | `cache` | 可随时重建 | 是 |
| 用户主动导出文件 | 用户选择的导出目录 | 用户资产 | 否 |

`generated` 只保存应用自动生成但尚未由用户另存的内容。用户点击“导出”后必须让用户选择目标目录，不得静默覆盖既有文件。

## 7. 开发版与发布版分流

### 7.1 开发版

所有开发版入口都必须明确传入 `--selplat-root=<SELPLAT_ROOT>`，包括源码热更新、编译桌面版、开发安装包和开发压缩包版。开发版统一按《工程临时目录规范》使用：

```text
<SELPLAT_ROOT>/cache/<applicationId>/
<SELPLAT_ROOT>/build/<applicationId>/
<SELPLAT_ROOT>/OPTION/temp/<applicationId>/执行日志/
<SELPLAT_ROOT>/OPTION/temp/<applicationId>/临时材料/
<SELPLAT_ROOT>/log/<applicationId>/归档日志/
```

当前 Windows 开发环境的实际根为：

```text
C:\opt\workspace\SELPLAT
```

开发版的日志、诊断、会话恢复点和临时材料必须继续写入该工程根的对应分类，方便开发者统一调试、检索和归档。开发压缩包在没有源码时可以创建所需运行数据目录，但不得把数据写入解压目录或平台发布目录。

`--selplat-root` 只用于开发版、测试或明确的内部工程协作。发布版不得携带、读取或推断该参数。

### 7.2 发布版

发布版必须使用第 5 章的平台默认目录。发布包不得要求 `.git`、`settings.gradle`、源码目录或 Node/npm 才能启动，也不得写入 `SELPLAT_ROOT`。

允许提供统一显式覆盖参数：

```text
--application-data-root=<absolutePath>
```

覆盖路径必须是绝对路径、通过路径逃逸校验并由启动方明确提供。发布包不得内置某台开发机的覆盖值。

### 7.3 发布版可选随包便携数据模式

只有用户明确选择“随包便携数据”时，才允许使用：

```text
<executableRoot>/_data/<applicationId>/
```

启用前必须验证目录可写。目录只读、位于 DMG、应用签名资源内部或策略禁止写入时，应停止并说明原因，不得静默回退到未知目录。

## 8. 运行路径清单

应用每次启动必须生成或刷新路径清单。开发版位置为：

```text
<SELPLAT_ROOT>/OPTION/temp/<applicationId>/运行路径/runtime-paths.json
```

发布版位置为：

```text
<dataRoot>/runtime-paths.json
```

最低字段：

```json
{
  "schemaVersion": 1,
  "vendorId": "SELPLAT",
  "applicationId": "ai-desktop",
  "applicationVariant": "release",
  "distributionMode": "installed",
  "dataRoot": "<absolute-path>",
  "configRoot": "<absolute-path>",
  "sessionRoot": "<absolute-path>",
  "generatedRoot": "<absolute-path>",
  "diagnosticsRoot": "<absolute-path>",
  "currentLogRoot": "<absolute-path>",
  "archiveLogRoot": "<absolute-path>",
  "cacheRoot": "<absolute-path>",
  "updatedAt": "<ISO-8601>"
}
```

清单要求：

- 使用 UTF-8 和绝对规范路径。
- 先写同目录临时文件，再原子替换正式文件。
- 不记录令牌、密码、用户输入正文或其他敏感内容。
- 所有路径必须来自同一次受控解析，不允许各模块分别猜测。
- `schemaVersion` 变化时必须提供兼容读取或迁移流程。

## 9. AI 自动定位和分析日志

AI 查找日志的顺序固定为：

1. 通过桌面主进程 IPC 获取当前运行路径清单。
2. 嵌入式 AI 子进程读取主进程传入的 `SELPLAT_RUNTIME_PATHS_FILE`。
3. 开发版未运行时，从明确的 `SELPLAT_ROOT/OPTION/temp/<applicationId>/运行路径/runtime-paths.json` 读取。
4. 发布版未运行时，根据平台标准路径读取 `runtime-paths.json`。
5. 上述入口均不可用时返回“日志路径不可用”，禁止扫描磁盘猜测。

桌面应用至少提供以下受控能力：

```text
getRuntimePaths
listRecentLogs
readLogRange
listDiagnostics
exportDiagnosticBundle
openLogDirectory
```

AI 默认只能读取本应用登记的日志和诊断路径。读取包外路径、其他应用数据或用户任意文件必须重新取得明确授权。

## 10. 日志结构与索引

运行日志优先使用 UTF-8 JSON Lines。每条事件至少包含：

```text
recordedAt
severity
applicationId
applicationVersion
sessionId
taskId（可空）
traceId（可空）
component
eventType
message
details（脱敏后）
```

`logs/current/index.json` 保存当前日志文件、启动时间、进程 ID、版本和最后写入时间。轮转后更新索引，不通过“扫描最新修改文件”决定当前日志。

日志必须轮转，禁止无限追加单个文件。保留期限和大小上限允许由应用配置，但不得自动删除仍被故障单、任务、发布批次或审计记录引用的证据。

## 11. 安全与权限

- Windows 使用当前用户可写目录，不请求管理员权限写运行数据。
- macOS 不写应用签名包内部，不绕过沙箱容器和系统权限。
- Linux 尊重 XDG 和当前用户权限。
- 日志必须对访问令牌、Cookie、Authorization、密码、私钥和用户敏感正文脱敏。
- 凭据进入 Windows Credential Manager、macOS Keychain 或 Linux Secret Service 等系统设施。
- 导出诊断包前必须再次脱敏，并生成包含文件清单和 SHA-256 的导出清单。

## 12. 升级、迁移和清理

1. 应用升级默认复用稳定 `<applicationId>` 对应的数据根。
2. 旧目录迁移必须记录来源、目标、版本、时间和结果。
3. 迁移成功前不得删除旧目录；失败时必须可以继续使用旧数据或明确回滚。
4. 多版本并行且数据结构不兼容时，使用版本化子目录，不得互相覆盖。
5. “清理缓存”只清理 `cacheRoot`，不得影响配置、会话、日志、诊断和生成文件。
6. “重置应用”必须展示将删除的分类并再次确认。

## 13. 打包与统一测试门禁

每个桌面应用至少验证：

1. 安装目录或解压目录保持只读时应用仍可启动。
2. Windows、macOS 及实际支持的 Linux 平台解析到规定目录。
3. 发布安装版和发布压缩包版不包含开发机绝对路径；开发版必须且只能使用明确传入的 `SELPLAT_ROOT`。
4. 删除缓存后应用可以重新生成并正常启动。
5. 移动发布压缩包目录后，平台默认数据仍可被找到；移动开发压缩包后，仍写入同一个 `SELPLAT_ROOT`。
6. `runtime-paths.json` 字段完整、路径合法且不包含敏感信息。
7. AI 能通过 IPC 或清单找到当前日志，不进行磁盘扫描。
8. 日志轮转、归档、脱敏和诊断导出符合规范。
9. 开发模式仍按《工程临时目录规范》写入工程根，发布模式不写工程根。
10. 任一目标平台未执行、失败或违规数不为零时，不得标记统一测试通过。

## 14. 禁止事项

- 禁止把 `C:\opt\workspace\SELPLAT` 或任意开发机路径写死到发布包。
- 禁止开发版因打包为安装包或压缩包而改写到发布版平台目录。
- 禁止发布版读取或写入 `SELPLAT_ROOT`。
- 禁止用当前工作目录代替用户数据根。
- 禁止让日志、缓存或会话散落在安装目录、桌面和下载目录。
- 禁止把日志和用户生成文件归为可随时删除的缓存。
- 禁止多个模块各自实现不一致的平台路径判断。
- 禁止 AI 递归扫描用户主目录寻找日志。
- 禁止安装版因找不到源码工程而拒绝启动。

## 15. 完成标准

- 安装文件与可变运行数据完全分离。
- Windows、macOS 和 Linux 使用各自标准用户目录。
- 开发模式与发布模式路径边界清晰。
- 缓存可删除，配置、会话、日志和生成文件不会被误删。
- AI 可以通过唯一运行路径清单和受控接口稳定定位日志。
- 安装、升级、迁移、清理和诊断导出均有可验证门禁。
