# SEL UI 接入规范

## 1. 目标

本规范定义 SELPLAT 新建和既有工程接入 SEL UI 时的唯一源码、主题、统一令牌、公共控件、分语言装配、构建打包和验证边界。

目标是：

- SEL UI 只保留一份正式源码，应用不得复制公共主题或控件。
- Java 与 Node 使用符合各自构建体系的接入方式，但消费同一主题契约和公共控件。
- 新工程已有的稳定 UI 风格先匹配现有主题；确有跨页面或跨工程价值时才沉淀为新主题。
- 主题决定公共视觉，应用只维护页面结构、业务流程和业务专属内容。
- 迁移统一令牌时可以保持现有外观，不得为了套用令牌擅自改变已确认设计。
- 固定使用既有工程根，不为接入过程建立重复公共目录或应用私有 SEL UI 副本。

## 2. 唯一源码和固定目录

SEL UI 唯一正式源码根为：

```text
SELPLAT/shared/frontend/sel-ui/
```

现有职责保持为：

```text
shared/frontend/sel-ui/
├── src/core/                         # 公共内核、基础运行时、国际化和请求能力
├── src/components/                   # 公共浏览器控件
├── src/components/component-registry.json
├── src/theme/contract/               # 统一主题契约
├── src/theme/runtime/                # 主题登记和切换运行时
├── src/theme/packs/<theme-id>/       # 公共主题包
└── src/assets/                       # 公共主题和控件素材
```

禁止建立 `apps/<工程名>/sel-ui`、`shared/ui`、`shared/themes`、`shared/frontend/common-ui` 等重复来源。

接入产生的数据仍遵守《工程临时目录规范》：

- 可重新生成的前端缓存进入 `cache/<工程名>/`。
- 编译、渲染和安装包产物进入 `build/<工程名>/`。
- 测试过程和临时截图进入 `OPTION/temp/<工程名>/`。
- 终态测试与审计结果进入 `log/<工程名>/归档日志/`。
- `apps/<工程名>/` 只保留应用永久源码、正式测试、配置和接入代码。

## 3. 职责边界

### SEL UI 主题负责

- 基础颜色、语义颜色和强调色。
- 字体、七级语义字号、字重和行高。
- 表面、边框、圆角、阴影、透明度和发光效果。
- 明暗模式、Accent、Density 和公共素材映射。
- 公共控件的悬停、聚焦、选中、禁用、成功、警告和错误视觉。

### SEL UI 公共控件负责

- 可以跨页面复用的 DOM、CSS、事件、键盘、焦点和销毁生命周期。
- Panel、Tree、Grid、Tabs、Window、Tooltip、Dropdown、Confirm Dialog 等已登记能力。
- 公共控件自身的可访问性、主题感知和统一交互。

### 应用工程负责

- 页面舞台、区域排列、窗口组成和响应式布局。
- 业务字段、业务接口、业务状态和业务流程。
- 把标准数据、选项和回调传给公共控件。
- 只对本应用成立、没有公共价值的业务专属表现。

应用不得复制公共控件的 DOM、事件和主题样式，也不得用应用 CSS 建立第二套公共视觉。

## 4. 新工程 UI 的主题判断

新工程接入前必须按以下顺序判断：

1. 检查已登记主题能否通过 `theme / mode / accent / density` 表达当前设计。
2. 只有页面排列或少量业务差异时，继续使用现有主题。
3. 现有主题无法表达，且新视觉体系稳定、完整并具有跨页面或跨工程价值时，才创建新主题。
4. 创建前检查近义主题，禁止以工程名为由复制颜色略有差异的主题。
5. 新主题只接收公共视觉，不接收工程名称、业务实体、接口地址、状态机或应用页面选择器。

以下情况不得创建新主题：

- 只是一个按钮、面板或页面位置不同。
- 只是单个业务状态需要特殊颜色。
- 只是一次性页面或实验视觉。
- 现有主题增加合法 Accent 或模式即可满足。
- 尚未确认是否长期使用。

## 5. 新主题包结构

新主题统一进入：

```text
shared/frontend/sel-ui/src/theme/packs/<theme-id>/
├── manifest.js
├── theme.css
├── modes/
│   ├── dark.css
│   └── light.css
└── README.md
```

只有存在真实主题独占素材时才建立：

```text
shared/frontend/sel-ui/src/assets/themes/<theme-id>/
```

要求：

- `<theme-id>` 使用稳定、小写、短横线命名，不使用机器名、用户 ID 或临时任务名。
- `manifest.js` 登记主题 ID、名称、分类、默认模式、Accent、Density、模式和素材。
- `theme.css` 只声明风格级公共令牌，不包含应用布局或业务选择器。
- `modes/dark.css` 与 `modes/light.css` 提供各自基础颜色、文字和语义状态。
- 不支持某个模式时必须明确说明并经过审查，禁止提供空模式或伪造模式。
- 素材路径必须能由 Java 静态资源和 Node 构建结果一致解析。

## 6. 统一令牌迁移

应用现有 UI 接入时，先建立真实视觉清单，再替换引用：

```text
应用硬编码视觉值
↓ 分类
SEL UI 已有语义令牌
↓ 语义确实缺失
新增公共或主题扩展令牌
↓
应用选择器只消费令牌
```

必须迁移字体、语义字号、字重、行高、表面、边框、圆角、阴影、透明度、发光、交互状态和语义状态色。

禁止：

- 用近似令牌替换后导致已确认界面变色。
- 把业务含义写入颜色令牌名称。
- 在应用内为公共组件重新声明固定色值。
- 保留新旧两套颜色体系作为兼容分支。
- 可读文字继续写像素字号，绕过七级语义文字契约。

如果现有令牌无法表达渐变、半透明面板或主题特有发光，应新增语义清楚的主题扩展令牌，不得通过错误复用改变视觉。

## 7. 保持现有外观的迁移门禁

既有 UI 整理为新主题时，第一阶段只改变视觉值来源，不改变页面结构和真实数值：

1. 在原实现下建立关键页面截图基线。
2. 记录真实颜色、字体、几何、阴影、透明度和各交互状态。
3. 使用相同真实值建立新主题包和模式。
4. 将应用硬编码值逐项替换为 SEL UI 令牌。
5. 在相同操作系统、窗口尺寸、缩放、语言和数据状态下重新截图。
6. 对关键区域执行像素或结构化视觉对比。
7. 差异未经确认时不得以“已经令牌化”为由接受视觉退化。

设计优化必须作为独立后续任务，禁止把主题接入与视觉改版混成一次不可审计修改。

## 8. Java/Gradle 工程接入

Java 工程通过 SEL UI 公共资源模块接入，不通过 Node 安装主题，也不复制静态文件。

当前正式交付链为：

```text
shared/frontend/sel-ui/src/**
↓ Gradle 公共资源构建
META-INF/resources/sel/**
↓ Java Web 静态资源映射
/sel/**
```

Java 页面按登记顺序加载：

1. `core` 基础 CSS。
2. `theme/contract` 统一主题契约。
3. 实际使用的公共组件 CSS。
4. 已登记主题的 `theme.css` 和模式 CSS。
5. `selKernel.js` 与基础运行时。
6. Theme Registry。
7. 已登记主题 Manifest。
8. Theme Manager。
9. 实际使用的公共组件 JavaScript。
10. 应用装配脚本。

示意引用：

```html
<link rel="stylesheet" href="/sel/theme/contract/selThemeContract.css?v=<资源版本>">
<script src="/sel/core/selKernel.js?v=<资源版本>"></script>
```

要求：

- Java 工程通过 Gradle 依赖获得公共资源 JAR。
- 页面只引用 `/sel/**`，不引用本机源码绝对路径。
- 主题或控件内容改变时，全部真实消费页面同步更新资源版本标识。
- 禁止复制 `/sel` 文件到应用 `static` 目录。
- 禁止建立第二套主题管理器或公共控件命名空间。

## 9. Node/Vite/Electron 工程接入

Node 工程使用自己的模块构建和打包方式，不经过 Java 资源 JAR，但必须消费同一 SEL UI 源码和主题契约。

Node 接入必须具有一个正式、可检查的发布出口，由构建配置解析 SEL UI 源码、样式和素材。禁止应用长期使用跨目录深层相对路径引用内部文件。

如果建立 Node 包出口：

- 包名固定为 `@selplat/sel-ui`。
- 通过 `exports` 公开基础令牌、主题契约、主题包、运行时、已登记组件和必要素材。
- 未登记到 `exports` 的源码为内部实现。
- 正式出口创建并验证前，禁止在应用代码中假装该包已经可用。
- Node 出口只是同一 SEL UI 源码的发布适配，不得形成第二份源码。

Node 主题加载顺序固定为：

```javascript
import "@selplat/sel-ui/theme/tokens";
import "@selplat/sel-ui/theme/contract";
import "@selplat/sel-ui/theme/states";
import "@selplat/sel-ui/theme/typography";
import "@selplat/sel-ui/theme/<theme-id>";
import "@selplat/sel-ui/theme/<theme-id>/<mode>";
```

`theme/tokens` 必须由宿主直接加载并位于合同和主题包之前；CSS 嵌套导入可以服务 Java 静态资源链，但不得成为 Node 生产运行时取得基础令牌的唯一方式。

Node 构建必须：

- 让 Vite、Electron 或其他浏览器构建器收集实际使用的 CSS、JavaScript和素材。
- 处理开发服务器、文件协议、HTTP 预览和安装包资源路径差异。
- 缓存进入 `cache/<工程名>/`，构建结果进入 `build/<工程名>/`。
- 安装包只携带实际运行资源，不携带 SEL UI 测试、Gradle、Java、源码映射或整个 `shared`。
- 验证生产构建和真实安装包，不得只验证开发服务器。

Java 与 Node 可以使用不同加载器，但主题 ID、令牌语义、Manifest 数据和公共控件行为必须一致。

## 10. React 接入

React 工程可以使用 SEL UI 主题和控件，但必须尊重原生控件的挂载与销毁生命周期。

主题适配层负责：

- 读取并设置 `theme / mode / accent / density`。
- 监听 `selTheme:change` 并同步 React 状态。
- 在根节点设置 SEL UI 所需的数据属性。
- 卸载时清理事件监听。

原生公共控件只有两种合法接入方式：

1. 已有正式 React 包装组件时，直接使用包装组件。
2. 尚无包装组件时，通过 `ref + effect` 调用已登记 API，并在清理阶段调用真实销毁入口。

禁止把原生控件假装成不存在的 JSX 组件、复制公共 DOM/CSS/键盘逻辑、重复挂载或卸载后遗留全局事件和浮层。

只有出现真实 React 调用方且适配语义稳定时，才在 SEL UI 内建立 React 适配目录；禁止预先创建空适配层。

## 11. 接入后使用公共控件

接入完成后可以直接使用 SEL UI 已登记控件，但必须加载硬依赖并遵守公开 API。

### Java 或原生浏览器页面

加载 SEL UI 运行时和对应组件后，通过 `window.sel` 已登记 API 调用。应用只传宿主节点、标准数据、选项和回调。

### Node 浏览器渲染层

通过正式 Node 发布出口装入同一运行时和组件，再调用已登记 API；Electron 主进程不得操作 DOM。

### React 页面

优先使用正式 React 包装组件；没有包装时使用受控生命周期适配，不复制组件实现。

新增或修改公共控件必须：

1. 检查 `component-registry.json` 是否已有近义能力。
2. 确认具有真实跨页面复用价值。
3. 登记稳定 ID、目录、JS、CSS、API、硬依赖、主题感知和可访问性。
4. 实现公开 API 和销毁生命周期。
5. 更新真实调用方和资源顺序。
6. 执行公共控件边界门禁及真实页面交互测试。
7. 删除应用内被替代的私有实现，不保留兼容代码。

## 12. 素材、字体和个性化

- 主题独占素材进入 `src/assets/themes/<theme-id>/`。
- 组件专属素材进入 `src/assets/components/<component>/`。
- 至少被两个公共能力真实复用的素材才进入 `src/assets/shared/`。
- 用户独立选择的页面背景进入 `src/assets/backgrounds/`。
- 图标、字体和图片必须有明确许可来源并随 Java 或 Node 产物交付。
- 禁止应用复制同一素材后改名保存。

SEL UI 主题状态统一使用：

```text
theme
mode
accent
density
```

应用可以声明默认值，但不得建立平行状态名称或绕过主题管理器批量改写颜色。个性化持久化由宿主通过正式接口保存，不得写入主题包源码。

## 13. AI Desktop 新主题示例

AI Desktop 当前 Developer 视觉可以整理为公共工作台主题：

```text
shared/frontend/sel-ui/src/theme/packs/developer-workbench/
├── manifest.js
├── theme.css
├── modes/dark.css
├── modes/light.css
└── README.md
```

边界如下：

- 深色面板、青色强调、紫色辅助、边框、发光、字体和状态视觉进入主题令牌。
- 资源管理器、聊天区、Context 面板、任务列表和输入区的位置与结构留在 AI Desktop。
- Fluent 图标继续作为应用图标来源，不归入主题。
- 第一轮使用当前真实 CSS 数值建立主题，保证视觉不变。
- 令牌化后不得保留平行硬编码颜色作为兼容路径。

## 14. 测试和验收

### 公共源门禁

- 主题和组件只有一个源码来源。
- 新主题 Manifest、模式、样式和素材完整。
- 新公共组件已登记，无未知目录和未登记 API。
- 应用不存在被替代的公共视觉或控件副本。

### 主题与视觉门禁

- 默认主题、明暗模式、Accent 和 Density 正确。
- 可读文字使用统一语义文字令牌。
- 悬停、聚焦、选中、禁用及语义状态可辨识。
- 主题切换后没有固定色值残留。
- 既有 UI 迁移前后在相同环境和数据下截图对比。
- 未经确认的像素或结构差异不得通过。

### Java 门禁

- Gradle 公共资源构建通过，`/sel/**` 真实可访问。
- 页面资源顺序、版本标识和运行时登记正确。
- 应用没有复制 SEL UI 静态文件。

### Node/Electron 门禁

- 类型检查和生产构建通过。
- 正式出口和素材解析通过。
- 安装包可以离线加载主题和控件。
- 安装包不包含 Java、Gradle、SEL UI 测试、源码映射、缓存或整个 `shared`。

### React 门禁

- 适配器只挂载一次并在卸载时完整销毁。
- 主题变化同步 React 状态。
- 没有重复 DOM、全局监听和残留浮层。
- 真实交互、键盘、焦点和可访问性回归通过。

Windows、macOS、Linux 中实际支持的平台分别验证字体、缩放、素材和窗口表现。测试过程与结果按照《工程临时目录规范》流转；任一必需平台未执行、失败或阻断时不得标记统一测试通过。

## 15. 禁止事项

- 禁止每个新工程创建自己的公共主题根。
- 禁止把 SEL UI 源码复制进应用。
- 禁止 Java 项目通过 Node 安装公共资源。
- 禁止 Node/Electron 打入 Java 资源 JAR 或整个 `shared`。
- 禁止应用长期深层相对引用 SEL UI 内部源码。
- 禁止页面私造已有公共控件。
- 禁止为了主题接入改变已确认 UI 外观。
- 禁止主题包包含应用布局、业务数据或接口。
- 禁止为没有真实调用方的未来框架预建空目录。
- 禁止保留已被统一令牌或公共控件替代的兼容代码。

## 16. 完成标准

- SEL UI 仍是唯一公共前端源码根。
- 应用通过所属语言的正式方式接入。
- Java 与 Node 消费同一主题 ID、令牌语义、Manifest 和公共控件行为。
- 新工程 UI 已先匹配现有主题，只有满足公共价值时才形成新主题。
- 应用只保留业务结构和适配代码，不保留公共视觉副本。
- 已登记公共控件可以直接使用，并具有正确装配和销毁生命周期。
- 既有 UI 令牌化前后符合已确认视觉基线。
- 缓存、构建、测试过程和历史归档进入规定目录。
- 全部目标平台、生产构建和真实安装包门禁通过。
