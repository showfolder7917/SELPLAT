# 当前专题技术卡点解除后的页面状态复验

## 变更与预期

- 在持久异常全部标记为 `resolved` 后，技术恢复状态保留问题次数和证据，但设为非活动；缺失或仍未解除的事件不得提前收口。
- 应用重启时，即使旧事件已从待处理队列退出，也要依据持久事件状态收口旧提示；页面不再显示“令狐老祖处理中／系统重试写入令狐交接”。
- 原提案最终验收仍以独立验收证据为准，不能因卡点解除而直接显示通过。

# 令狐持续自修与测试数据清空专题合并

## 目标与边界

- 同一验证路径在两次修正后仍失败时，令狐只读重查原验收要求、生产调用链、测试替身和页面生命周期；保留原始失败证据，再依据新结论修复一次。仍是同类失败则停止循环并交回接管。
- 当前专题代码合入主工程，清空测试运行态前展示各类实际清理数量和候选清理警告；人物对话、训练语料、登录、设置、工作区、规则、源码与工程审计继续保留。
- 清理成功后经第二次确认才受控重启；若运行时销毁后清理失败，按失败码受控恢复，避免应用停留在不可用状态。

## 发现与修正

- 原交互测试的 `confirmTestDataResetRestart` 替身只写标记，不执行进程重启；此前将同一 Renderer 的后续观察当成真实重启证据。该限制已写入令狐调查与修复提示，并用执行器测试覆盖独立重查时机。
- 完整交互测试中，清空用例结束时设置浮层仍打开，使下一项布局用例的点击变成关闭；补上状态复位后 40 项连跑通过，未放宽布局位置与溢出断言。
- 测试数据清理仅对白名单运行投影执行删除；数据库版本、对话与训练语料由现有持久化测试核对保留。
