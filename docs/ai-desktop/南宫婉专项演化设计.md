> 适用产品：AI Desktop
>
> 文档性质：现有系统事实基线 + 补充能力设计
>
> 基线日期：2026-08-28
>
> 保留文档：本文件
>
> 合并来源：《南宫婉专项演化设计》《南宫婉自动演化设计方案》

## 1. 核心结论

南宫婉专项演化继续沿用现有系统线路，不改接口、不换状态机、不改变审批人和审批顺序。新增的“专题执行群”只是现有专题、提案、审批、任务、测试、发布和验收记录的统一协作视图，不是第二套业务系统。

完整职责链保持为：

```text
南宫婉与 Codex 完整会话组
→ 韩立分析并向南宫婉逐轮提问
→ 证据、边界和验收条件充分后，韩立确立专题
→ 南宫婉登记专题、形成提案
→ 进入现有方向审批流程
→ 审批通过后返还南宫婉
→ 南宫婉拆分并分发任务
→ 执行成员返回原始结果
→ 所有任务返还南宫婉后，交给令狐统一测试、打包、发布、重启和恢复
→ 韩立按真实用户路径进行结果验收
→ 通过后归档；不通过则返还南宫婉继续纠偏
```

专题执行群把这条链上的可读消息和状态变化按时间顺序聚合，使韩立能看到“谁在做什么、做到哪里、下一步是什么、哪里阻塞”，但所有业务写入仍由原服务完成。

## 2. 不变边界

本次补充设计明确不做以下变化：

- 不替换 `NangongEvolutionFacade`、Store、统一事件中心或现有 Renderer 工作台。
- 不新增一套专题、提案、审批、任务、测试或发布状态机。
- 不改变手动审批人与自动审批人的身份。
- 不把方向审批、执行领域评审、Codex 命令授权和结果验收合并为一种审批。
- 不让群消息直接修改业务状态；群内动作只能调用或跳转到现有入口。
- 不把专题、审批、任务、测试、发布和异常记录伪装成人物对话或训练语料。
- 不因自动化开关开启而跳过工程授权、审批、测试或验收门禁。

## 3. 角色职责

| 角色 | 固定职责 | 不承担的职责 |
|---|---|---|
| 韩立 | 综合完整会话组、制定问题、逐轮发问、判断是否继续、确立专题、监控执行、最终验收 | 不代替南宫婉拆分任务，不代替令狐完成测试发布 |
| 南宫婉 | 回答研讨问题、登记专题、形成方案、提交提案、审批后拆分依赖、分发任务、汇总结果 | 不在审批前修改工程，不绕过执行与测试门禁 |
| 用户 | 在手动模式完成方向审批，对真实业务选择与高风险操作作出决定 | 不需要承担系统可以自行调查的事实核对 |
| Codex 与协作成员 | 执行具体分析、修改和验证任务，返回原始执行数据 | 不擅自改变已审批方向和专题边界 |
| 令狐 | 审核任务计划冲突，执行统一测试、打包、发布、重启和恢复门禁 | 不替代韩立进行最终业务验收 |
| 系统 | 持久化状态、事件、恢复点、稳定关联和派生视图 | 不用机械阈值替代人物的语义判断 |

## 4. 会话研讨与专题确立

### 4.1 来源读取

韩立按完整会话组读取南宫婉和 Codex 会话，不能把全文检索命中的零散片段拼成伪会话。读取时保留来源、会话 ID、消息 ID、顺序和时间。

### 4.2 每轮研讨事实

每轮至少保存：

- 韩立原问题与发问依据。
- 南宫婉原回答。
- 韩立基于回答作出的判断。
- 下一步决定：继续追问、确立专题或阻塞。

轮次数可以限制，也可以无限，但轮次数不能替代判断。证据不足时不得为了完成自动化指标机械建立专题。

### 4.3 专题建立门槛

只有韩立确认目标、现状证据、范围、排除项、风险、依赖和验收条件充分后，候选内容才能从“研讨中”进入正式专题。建立专题的理由必须完整且可追溯。

## 5. 专题池与全生命周期案卷

专题池是长期存在的专题容器，不为每个专题重复建立一个池。每个专题是一份全生命周期案卷，至少关联：

- 来源会话原 ID 与不可变原文快照。
- 韩立与南宫婉的全部研讨轮次。
- 韩立确立专题的理由。
- 专题内容与历次方案版本。
- 审批、退回、补充和纠偏记录。
- 南宫婉的任务拆分、依赖和分发记录。
- 执行人、会话、命令状态、文件变化、日志和产物地址。
- 测试、集成、打包、发布、重启和恢复记录。
- 韩立的操作路径、视觉检查、体验检查和验收结论。

原始记录只追加、不覆盖。当前状态、摘要、计数和进度是原始记录上的派生视图。

## 6. 南宫婉提案标准

| 字段 | 要求 |
|---|---|
| 标题 | 简明表达专题和演化方向 |
| 类型 | 规则演进、规则优化、规则重构、目录演进、代码修正或 Bug 修复 |
| 来源 | 记录为 `nangong`；令狐返还修复提案时记录为 `linghu` |
| 事实证据 | 列出代码、规则、日志、测试或用户确认事实，区分事实、推断和待验证项 |
| 目标与方向 | 说明要解决什么，以及推荐方向为什么成立 |
| 影响边界 | 明确涉及范围、排除范围和依赖 |
| 风险与回退 | 说明失败表现、兼容风险和恢复方式 |
| 验收条件 | 定义可检查、可记录的结果 |

提案必须关联专题、演化轮次和来源会话快照。提案优化生成新版本，不能覆盖旧版本。

## 7. 现有审批流程保持不变

统一治理只统一审计信封，不合并业务状态机。

### 7.1 方向审批

- 审批阶段：`direction`。
- 手动来源：`manual-user`，审批人是用户。
- 自动来源：`automatic-han-li`，审批人是韩立。
- 合法决定：`approved`、`rejected`、`supplement-required`。
- 事实不足时必须退回补充，自动审批不等于自动通过。
- 审批通过后提案先返还南宫婉，不能直接绕过南宫婉开始分发。

### 7.2 相互独立的审批领域

- 韩立确立专题是方向决策前的专题建立判断。
- 演化方向审批使用上述现有流程。
- 协作成员的方案评审属于执行领域评审。
- Codex 命令授权继续保留接受、拒绝和项目信任语义。
- 韩立对落地结果的验收属于 `result` 阶段。

专题执行群只能展示这些决定和进入原页面的链接，不能在群投影中自行创建一种新审批结论。

## 8. 审批后的任务拆分与分发

审批通过只打开现有分发窗口。南宫婉按照模块、依赖和验证边界拆成最小可独立执行任务。

| 要求 | 规则 |
|---|---|
| 方向一致 | 任务不得改变已审批目标、边界和验收条件 |
| 工作区冻结 | 使用专题已冻结工作区，不使用自动化开关所在上下文替代 |
| 最小拆分 | 每个任务能够独立分析、实施和返回结果 |
| 依赖明确 | 保存依赖链；必须同时完成的任务登记原子组 |
| 重叠检查 | 令狐在分发前检查任务计划和预计文件范围，存在冲突时阻断 |
| 稳定关联 | 每个任务保留专题、提案、演化轮次、原子组和依赖标识 |
| 原路返回 | 每个结果返回南宫婉，不以单个任务成功代表本轮完成 |

只有全部任务返回并满足原子批次条件后，本轮才允许一次性封存并交给令狐统一门禁。

## 9. 令狐门禁与韩立最终验收

令狐负责统一测试、打包、发布、重启和恢复检查。任务完成或测试通过都不等于专题完成。

令狐门禁完成后，提案进入 `pending-acceptance`。韩立根据专题目标、客户关注点、已识别页面与控件、专业检查规则和已验证项目经验生成本轮验收计划，再打开真实应用按用户路径完成结果审批与验收，包括功能、数据、交互、视觉、异常和恢复证据。只有适用检查项完成且韩立验收通过后，专题和提案才能进入 `completed`。

验收不通过时，结果携带检查对象、入口路径、复现步骤、截图地址、实际结果、期望结果、严重程度和原始证据地址返还南宫婉继续纠偏，不丢失已完成的历史轮次。南宫婉据此形成修正提案，仍然进入现有审批、拆分、分发、令狐门禁和韩立复验流程。

## 10. 自动化开关相互独立

以下开关分别持久化，不能互相隐式开启：

- 南宫婉自动演化。
- 南宫婉来源提案自动审批。
- 令狐来源修复提案自动审批。
- 审批后的自动任务分发。

手动分发不依赖自动化工作区。任何开关关闭时，只停止对应自动动作，不删除历史记录、待处理提案或恢复点。

## 11. 专题执行群：补充协作视图

### 11.1 定位

专题执行群是一专题一群的统一时间线。它连接真实人物回复和既有业务事件，让所有参与者在一个位置看到专题全貌。

它是人物可读消息的协作窗口、现有业务状态的投影视图，以及原审批页、任务页、测试页和专题案卷的导航入口。它不是新的审批流程、任务调度器、测试服务、发布服务，也不允许用聊天消息旁路驱动状态迁移。

### 11.2 入群时机与成员

韩立确立专题时创建或绑定专题群，并把专题 ID、来源会话地址和冻结快照地址作为群头信息。默认成员为韩立、南宫婉、令狐、系统以及本专题实际执行成员；用户可查看并在需要人工决定时参与。

### 11.3 群内可见内容

| 内容类型 | 展示内容 | 权威来源 |
|---|---|---|
| 人物回复 | 韩立问题、南宫婉回答、执行成员结论、令狐门禁结论 | 人物会话或协作回复 |
| 专题建立 | 目标、边界、验收条件、来源会话与快照地址 | 现有专题案卷 |
| 提案变化 | 版本、提交人、摘要、当前状态和详情入口 | 现有提案记录 |
| 审批变化 | 审批阶段、审批人、决定、意见和审批页入口 | 现有审批记录 |
| 任务变化 | 负责人、当前动作、下一步、阻塞、依赖和任务页入口 | 现有任务记录 |
| 门禁变化 | 测试、打包、发布、重启、恢复的摘要和证据入口 | 现有测试与发布记录 |
| 结果验收 | 韩立验收路径、通过或退回原因、证据入口 | 现有结果审批记录 |

长日志、命令输出和原始载荷不复制进群，只显示简要结果和原记录地址，避免时间线被噪声淹没。

### 11.4 群消息最小信息

每条业务投影至少显示发生时间、真实来源、当前动作、当前状态、下一步、下一负责人、阻塞原因、稳定 ID 和原始记录入口。

### 11.5 群内动作规则

群中的“查看审批”“查看任务”“查看测试”“查看来源会话”等动作只跳转到现有页面。若后续提供“提交审批”“退回补充”“分发”等快捷动作，也必须调用同一个现有业务接口并遵守原权限、参数校验和状态前置条件，禁止在群组件中复制业务逻辑。

### 11.6 韩立监控职责

韩立通过群时间线持续判断是否有人尚未接收任务、是否存在依赖或文件范围冲突、是否有任务长时间无进展、是否全部任务已经返回南宫婉、是否令狐门禁完成且应用恢复，以及是否已有足够证据进入最终验收。

韩立的监控决定可以触发原有提醒、调查、退回或验收入口，但不能直接篡改其他角色的业务记录。

### 11.7 界面验收与经验增长投影

专题进入 `pending-acceptance` 后，群内补充展示韩立验收计划及其进度：已识别对象、适用检查项、真实操作结果、截图和运行证据地址。发现失败项时，群卡片显示复现步骤、当前严重程度、返还给南宫婉的修正提案以及后续令狐门禁和韩立复验状态。

修复并复验成功后，群内只显示“形成候选项目经验”的投影及证据链，不直接宣布已经生成通用规则。候选经验的复用、反例、范围调整和治理提升继续引用各自权威记录，避免群消息成为规则事实来源。

## 12. 对话、业务数据与训练语料边界

人物间真实可见的问答可作为对话保存，并按现有规则进入训练语料。专题、提案、审批、任务、测试、发布、异常、审计和状态投影仍属于业务数据。

群时间线可以同时展示两类内容，但存储和训练边界不能混淆：

- 人物对话保存原始消息及来源关联。
- 业务卡片只保存对既有记录的引用和必要显示快照。
- 业务状态不能因显示在群内就写入对话训练表。
- AI 训练摘要不能替代专题、审批或测试的权威原始数据。

## 13. 状态与恢复

现有专题状态保持为：

```text
registered
investigating
pending-approval
supplement-required
rejected
approved
executing
verifying
pending-acceptance
completed
blocked
```

群自身只维护读取水位、展示状态和未读状态，不维护第二套专题状态。应用重启后从既有事件、案卷和任务记录重建群时间线；投影失败不得影响原业务流程继续运行。

## 14. 界面结构

沿用 AI Desktop 当前独立专题演化工作区和“左侧单树、右侧内容”结构。

- 左侧树补充“专题执行群”入口，挂在当前专题下，不重建功能模块线路。
- 右侧群头展示专题标题、状态、来源会话地址、当前负责人和下一步。
- 中部按时间展示人物消息与业务投影卡片，可按人物、任务、审批、测试筛选。
- 业务卡片提供现有详情页入口。
- 底部输入区仅发送允许的人物消息；业务动作使用明确按钮并调用现有接口。

## 15. 已实现与待补充边界

### 15.1 当前已有事实

- 韩立研讨、南宫婉回答、专题候选与确立。
- 专题池、来源快照和全生命周期案卷基础。
- 南宫婉与令狐来源提案。
- 方向审批和结果审批。
- 审批后返还南宫婉、任务拆分与分发。
- 工作区冻结、文件重叠阻断、依赖和原子批次。
- 全任务返回、令狐统一门禁和韩立最终验收。
- 独立持久化的自动化开关和恢复机制。

### 15.2 本文新增、尚待实现

- 一专题一群的统一人物消息与业务事件时间线。
- 群头来源会话与冻结快照入口。
- “当前动作—下一步—负责人—阻塞”的统一可读投影。
- 从群卡片跳转既有审批、任务、测试和验收页面。
- 群未读、筛选、投影恢复和一致性检查。
- 韩立根据专题、关注点、控件规则与项目经验自动生成界面验收计划。
- 韩立打开真实应用完成点击、滚动、窗口调整、视觉和数据检查。
- 验收失败证据沿现有 `result` 流程返还南宫婉，并在修复后重新进入令狐门禁和韩立复验。
- 将复验成功的问题发现沉淀为项目检查经验，并在多场景验证和规则治理后提升为稳定专业规则。

在程序与测试完成前，不得把这些补充能力描述为已经上线。

## 16. 验收标准

### 16.1 现有流程回归

- 韩立只有在证据、边界和验收条件充分后才能确立专题。
- 南宫婉提案仍进入现有方向审批。
- 审批通过后仍先返还南宫婉，再拆分与分发。
- 所有任务必须原路返回，不能以单任务成功提前封存本轮。
- 令狐完成统一门禁、应用恢复运行后，仍由韩立最终验收。
- 自动演化、两类来源自动审批和自动分发保持独立。

### 16.2 专题执行群验收

- 群中可以按时间看到真实人物回复和既有业务状态投影。
- 每张业务卡片能回到唯一原始记录。
- 韩立可以明确看到当前负责人、当前动作、下一步和阻塞。
- 群内快捷动作复用现有接口和权限，不产生旁路状态。
- 群投影失败不影响原审批、分发、测试和验收流程。
- 业务投影不进入人物训练语料。
- 长日志只显示摘要和原记录地址。

### 16.3 韩立真实界面验收与自动增长

- 令狐门禁完成后，韩立能够识别本次涉及的页面、控件、数据流程和运行状态，并生成适用检查计划。
- 韩立使用真实入口、窗口尺寸、点击、滚动、键盘和数据结果完成检查，不以代码或测试报告替代操作验收。
- 弹窗或侧栏内容溢出时，韩立能够检查滚动是否真实存在、最后一个控件是否可达以及滚动能力是否可发现。
- 验收失败时，南宫婉收到完整复现证据并形成修正提案；审批流程、任务分发和令狐门禁保持不变。
- 未修复、未复验或纯 AI 猜测的问题不能提升为检查经验。
- 项目经验必须保留来源发现、修正提案、测试和复验地址；经过多个独立场景验证后才可进入稳定规则治理。
- 新反例能够触发经验降级、适用范围缩小、替代或退役，不能让错误检查能力无限累积。
