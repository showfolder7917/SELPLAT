# 韩立认知演化系统估值报告

> 估值基准日：2026-08-28
>
> 评估对象：SELPLAT AI Desktop 中以韩立、南宫婉、令狐和 Codex 协作为核心的认知演化系统
>
> 报告性质：内部阶段评估，不是融资估值、资产评估或投资建议

## 1. 结论摘要

当前系统已经超过“只有想法和文档”的概念阶段，处于**可运行的工程原型 / 早期产品原型**阶段。它已经具备真实的数据、契约、界面、协作流程和部分自动恢复能力，但尚未具备用收入、付费客户、留存、跨项目稳定性和单位经济性支撑高额商业估值的证据。

现阶段应把价值分成三层看待：

1. **已经形成的工程资产价值**：统一会话语料、专题研讨、提案、审批、任务分发、原子返回、统一测试与最终验收等真实实现。
2. **创始人知识与流程资产价值**：客户关注点、近期成熟观点优先、事实先行、完整闭环和角色分工等方法论。
3. **尚待证明的商业期权价值**：韩立自主设问、自主扩展、跨项目复用和降低人工协调成本的潜力。

不能把第三层潜力直接当成当前企业价值。更合理的做法是按里程碑逐步解锁价值。

## 2. 评估证据边界

本报告依据当前工程、契约、测试和设计文档评估，不把未来计划当作已实现事实。

### 2.1 当前已有能力

- Codex、南宫婉、韩立来源统一标注的会话与回合主题结构。
- 用户原话保存、AI 摘要、稳定去重、近期优先和历史补齐基础。
- 韩立按完整会话组研讨、向南宫婉逐轮提问并确立专题。
- 专题来源快照、专题案卷、提案版本和审计关联。
- 手动/自动方向审批、审批后返还南宫婉、任务拆分与分发。
- 工作区冻结、任务依赖、原子组、预计文件重叠阻断。
- 全任务返回、令狐统一门禁和韩立结果验收。
- 自动演化、不同来源自动审批和自动分发的独立开关。
- 中断、失败和重启后的部分恢复基础。

### 2.2 仍属于待实现或待验证的能力

- 成熟的客户关注点模型与证据权重维护。
- 可复用的高质量提问轨迹和自主设问评估体系。
- 专业隐含要求库、自动验收计划及实现后真实界面操作闭环。
- 从问题复现、修复、复验到项目经验复用和稳定规则提升的可纠错自动增长机制。
- 一专题一群的统一人物消息与业务投影时间线。
- 多项目、多人、长周期的稳定运行数据。
- 外部客户付费意愿、留存、节省成本和交付提升证据。
- 明确的模型调用成本、维护成本和单位经济性。

### 2.3 数据量的解释限制

会话条数、主题数和数据库大小能够证明系统已经积累真实材料，但不能单独证明材料质量、训练效果或商业价值。关键指标应是材料是否带来更准确的问题、更少返工、更高任务完成率和更稳定的客户验收。

## 3. 当前阶段判断

| 阶段 | 判断 | 依据 |
|---|---|---|
| 概念 | 已越过 | 已有真实程序、数据、状态和测试，不再只是文档 |
| 工程 Demo | 已达到 | 可以展示端到端专题协作的主要链路 |
| 早期产品原型 | 正在进入 | 有持久化、恢复、界面和治理边界，但仍需统一体验和长期验证 |
| 可复制产品 | 尚未达到 | 缺少跨项目部署、标准化配置、稳定运营指标和外部用户验证 |
| 规模化商业产品 | 尚未达到 | 缺少收入、留存、成本结构、支持体系和合规证据 |

因此，当前最准确的定位是：

> 一套已经形成真实工程闭环、正在验证自主认知与多角色协作价值的早期产品原型。

## 4. 资产构成

### 4.1 软件与架构资产

- Electron 桌面端、主进程服务、契约、数据库和测试体系。
- 会话语料、专题研讨、审批、分发、验证和恢复的端到端关联。
- 分角色的职责边界和独立自动化控制。
- 对稳定 ID、幂等、失败恢复和审计证据的工程投入。

这部分适合用“重建成本”评估，但重建成本不等于市场愿意支付的价格。

### 4.2 数据与知识资产

- 客户原始会话和近期成熟观点。
- 主题、标签、意图和 AI 摘要。
- 南宫婉研讨、韩立问题、执行结果和验收证据之间的潜在轨迹。

其价值取决于来源授权、去重质量、语义准确性、可追溯性和实际提升效果。未经评测的数据不能按条数直接计价。

### 4.3 流程与审计资产

- 方向审批、执行评审、命令授权和结果验收相互分离。
- 任务必须返回原提案人、统一测试后再验收。
- 原始事实只追加，摘要和状态作为派生视图。

这部分能够降低自动化失控、责任不清和“代码完成即任务完成”的风险，是系统差异化的重要基础。

### 4.4 创始人和领域知识

系统中的大量规则来自长期纠正与工程经验，例如真实操作优先、近期观点优先、完整闭环、不要机械提问、不要保留无效兼容等。这些知识具有战略价值，但如果只存在于单一用户和单一项目中，可转移性仍然有限。

## 5. 估值方法

现阶段不适合使用收入倍数或成熟 SaaS 估值方法，因为尚无稳定收入和留存数据。建议同时使用三种视角：

### 5.1 重建成本视角

统计重新实现当前已验证功能所需的产品、架构、前后端、数据、测试和领域设计投入，并扣除：

- 尚未统一或仍需重构的部分。
- 缺少文档、测试或可移植性的部分。
- 对单一人员知识依赖过高的部分。
- 尚未证明可复用的数据和模型能力。

该结果表示“重做一套相近系统的成本”，不表示投资人或买方的成交价。

### 5.2 里程碑期权视角

对尚未证明的能力不给当前确定价值，只记录为条件性期权。每完成一个可验证里程碑，才提高价值判断。

### 5.3 商业验证视角

获得真实客户后，再用以下数据评估产品价值：

- 付费客户数与续费率。
- 每个专题的人力节省和交付周期变化。
- 提问命中率、返工率、任务完成率和最终验收通过率。
- 单个任务的模型、计算、存储和人工监督成本。
- 部署、支持、安全和合规成本。

## 6. 当前价值表达方式

在没有完整工时台账、外部成交对比和商业指标前，不应继续使用“当前值几千万、终局值几亿”一类精确区间。当前可以负责任地表达为：

- **工程价值**：已有多模块、持久化、测试和恢复组成的非平凡原型，价值显著高于概念文档。
- **产品价值**：能够进行内部演示和连续验证，但尚未证明外部可复制性。
- **商业价值**：目前主要是潜力，不能用数据规模或功能数量替代客户付费证据。
- **融资价值**：必须结合团队、市场、知识产权、增长、客户和成本单独评估，本报告不提供融资报价。

若确实需要人民币数字，应先完成独立的代码工作量盘点、第三方重建报价、知识产权审查和至少一轮外部客户验证，再形成区间。

## 7. 价值解锁里程碑

| 里程碑 | 必须取得的证据 | 解锁的价值 |
|---|---|---|
| M1：内部可靠闭环 | 多次专题从研讨到验收完整通过，失败可恢复且无数据重复 | 证明工程不是一次性 Demo |
| M2：韩立自主分析有效 | 与普通问答基线相比，关键问题命中率提高、无效问题减少 | 证明认知层产生增量 |
| M3：专业隐含要求有效 | 能提前发现滚动、遮挡、异常、恢复等历史未出现问题 | 证明系统能超出会话记忆泛化 |
| M4：真实验收闭环 | 韩立能生成检查计划、操作真实界面、携带证据返还修正并完成复验 | 证明验收不是静态报告 |
| M5：检查能力可纠错增长 | 复验成功的发现能在相似对象中复用，误判和反例能使经验降级、限缩或退役 | 证明系统可以成长且不会只增不减 |
| M6：跨项目复用 | 至少三个不同项目稳定运行，规则不依赖硬编码单一项目 | 证明可复制性 |
| M7：外部用户验证 | 外部客户持续使用并愿意付费或签署明确试点 | 证明市场需求 |
| M8：单位经济性成立 | 节省的人力与返工成本高于模型、维护和支持成本 | 证明商业可持续性 |
| M9：规模与治理 | 权限、隐私、审计、隔离、运维和支持体系通过评估 | 证明可规模部署 |

## 8. 建议的核心指标

### 8.1 韩立认知指标

- 关键问题命中率。
- 无需客户回答即可查明的事实问题比例。
- 重复、机械或无效提问比例。
- 客户纠正后是否采用近期有效观点。
- 隐含要求发现率和误扩展率。
- 验收计划适用检查项覆盖率。
- 真实界面操作完成率和证据完整率。
- 项目检查经验后续命中率、误判率、反例率和降级及时性。
- 从验收失败到修复复验通过的平均闭环时间。

### 8.2 专题执行指标

- 从研讨到专题确立的平均轮数与阻塞原因。
- 审批退回补充率及主要原因。
- 任务首次分发后的返工率。
- 原子批次完整返回率。
- 统一测试通过率、恢复成功率和最终验收通过率。

### 8.3 商业与成本指标

- 每专题节省的人时。
- 每专题模型调用、存储和计算成本。
- 人工监督时间。
- 部署和支持成本。
- 客户活跃、留存、付费转化和续费。

## 9. 主要风险与折扣因素

- **单一用户偏差**：当前关注点和会话主要来自一个稳定用户，泛化能力未经证明。
- **AI 语义误差**：主题、标签、摘要和判断可能偏离原意，必须保留原始证据和纠错机制。
- **成本风险**：长会话、多轮分析和多角色执行可能产生较高模型与存储成本。
- **复杂度风险**：流程过长会降低使用效率，专题执行群只能降低信息分散，不能掩盖流程复杂度。
- **安全与隐私**：会话、代码和执行日志可能包含敏感内容，需要明确授权、隔离和保留策略。
- **关键人依赖**：领域规则、操作习惯和系统知识集中在创始人时，会降低可转移价值。
- **市场风险**：通用 Coding Agent 能力快速进步，差异化必须由自主发现问题和可靠闭环的实测效果证明。
- **运维风险**：桌面环境、模型登录、数据库恢复、测试发布链任一不稳定都会影响整体可信度。

## 10. 下一阶段建议

1. 先稳定现有线路，不因新增专题执行群更换审批或任务流程。
2. 完成专题执行群的只读投影与详情跳转，让韩立能够监控现有链路。
3. 建立客户关注点、提问轨迹、验收计划、检查发现和分级经验的可评测数据结构。
4. 先实现“识别对象—生成计划—真实操作—证据返还—修复复验”，再开启经验自动增长。
5. 为自动增长建立提升、合并、反例降级、限缩、替代和退役门禁，禁止一次失败直接成为通用规则。
6. 选择一组真实复杂需求做对照测试，比较普通问答与韩立自主分析、真实验收和经验复用的效果。
7. 建立成本仪表：每轮模型用量、界面操作成本、每专题总成本、人工介入和返工。
8. 完成至少三个不同类型项目的连续验证，再讨论可复制产品估值。
9. 获得外部试点、付费或明确采购意向后，再形成融资或交易估值。

## 11. 战略潜力

系统真正有潜力形成差异化的不是“让多个 AI 分角色说话”，而是把以下能力连成可审计闭环：

```text
理解客户当前目标
→ 主动发现信息缺口和专业隐患
→ 提出真正有价值的问题
→ 把回答沉淀为专题、方案和任务
→ 监督执行、测试、恢复和真实验收
→ 从修复和复验结果形成可纠错的检查经验
→ 在后续相似任务中自动复用并持续修正认知
```

如果这条链能够在多个项目中稳定降低沟通成本、返工和遗漏，韩立将从对话助手升级为具备产品分析与研发协调能力的认知系统。这是值得持续投资验证的方向，但应由真实结果逐步证明，而不是由愿景提前定价。

## 12. 最终判断

当前最有价值的成果是：系统已经拥有一个可运行的多角色研发闭环基础，并开始把客户原话、分析、审批、执行和验收连接起来。

当前最缺的不是更大的愿景数字，而是三类证据：

1. 韩立确实能提出更好的问题。
2. 整个闭环确实能减少遗漏和返工。
3. 这种效果能够跨项目复制，并且收益高于运行成本。

取得这些证据后，系统的估值才会从工程资产和创始人能力，转化为可验证的产品与商业价值。
