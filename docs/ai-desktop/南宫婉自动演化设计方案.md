# 南宫婉自动演化设计方案

## 核心目标

自动演化不是从对话库直接发现或生成专题。韩立综合对话库中南宫婉和 Codex 的完整会话组，作为发问方与南宫婉开展多轮专题研讨；证据和边界充分后由韩立确立演进专项，再通知南宫婉登记专题池、拆解任务和分发实施。

固定职责：

- 韩立：综合对话库、制定问题、逐轮发问、判断是否继续、确立专项、发起实施和最终验收。
- 南宫婉：回答研讨问题、维护专题池、形成实施方案、拆解依赖、分发任务并汇总结果。
- Codex 与协作成员：执行具体开发、修改和验证任务，并返回原始执行数据。
- 令狐：执行统一测试、打包、发布、重启和恢复门禁。

## 主流程

```text
南宫婉与 Codex 完整对话库
→ 韩立按会话组综合上下文、纠正、矛盾和历史执行结果
→ 韩立生成首个需要问清的问题
→ 韩立向南宫婉发问
→ 南宫婉回答
→ 韩立判断、追问或纠偏
→ 多轮交流后韩立确立演进专项
→ 通知南宫婉登记专题池
→ 南宫婉形成方案、拆解依赖并分发任务
→ Codex 与协作成员实施
→ 令狐统一测试、打包、发布和重启
→ 韩立按真实用户路径操作验收
→ 通过归档，或驳回后继续纠偏
```

没有经过韩立研讨确立的候选内容只能处于“研讨中”，不能进入正式专题池，也不能拆解和分发任务。

## 韩立—南宫婉研讨模型

每轮必须保存以下原始事实：

- 韩立原问题及发问依据。
- 南宫婉原回答。
- 韩立基于回答作出的判断。
- 下一步是继续追问、纠正方向还是确立专题。

研讨轮次可以配置有限次数或无限模式，但轮次数不能替代 AI 判断。证据不足时不得为了达到自动化指标提前生成专题；需要继续调查或阻断时必须保留原因。

## 专题池

专题池是长期存在的专题容器。韩立每确立一个专项，南宫婉向专题池新增一个专题；不是为每个专题重新建立一个专题池。

每个专题是一份“全生命周期案卷”，至少包括：

- 来源对话的原 ID 和不可变原文快照。
- 韩立与南宫婉的全部研讨轮次。
- 韩立确立专项的原始理由。
- 专题内容与历次方案版本。
- 审批、退回、补充和纠偏记录。
- 南宫婉的任务拆解、依赖和分发记录。
- 执行人、模型、会话、命令、退出状态、文件变化、日志和产物。
- 测试、集成、打包、发布、重启和恢复记录。
- 韩立的操作路径、视觉检查、体验检查和验收结论。

原始记录只追加、不覆盖、不重写。专题标题、方案或任务后来改变时，旧版本继续保留；当前状态、摘要和进度是原始记录上的派生视图。

## 数据与查询边界

韩立读取对话库时必须按完整会话组查询，不能把 FTS 命中片段拼成伪会话。南宫婉会话和 Codex 会话可以来自不同表，但在韩立综合视图中按来源、会话 ID 和顺序完整呈现。

专题确立时同时保存来源引用和冻结快照：引用用于回到对话库，快照用于防止原会话迁移、删除或重新打包后导致专题证据丢失。

执行记录通过专题、提案和任务 ID 关联统一事件中心。专题页面既提供精简时间线，也允许展开查看每次问答、审批、执行、测试和发布的原始载荷。

## 审批与完成门槛

统一审批治理只统一审计信封，不合并业务状态机：

- 韩立确立专项属于方向决策。
- 协作成员方案评审属于执行领域评审。
- Codex 命令授权保留接受、拒绝和项目信任语义。
- 韩立对落地结果的操作验收属于结果决策。

任务执行完成不等于专题完成。只有令狐门禁完成、应用恢复运行，并由韩立按真实用户路径验收通过后，专题才能归档为完成；验收不通过则回到南宫婉继续纠偏。

## 创造力与安全边界

系统不使用固定收益分、关键词频次、用户符合度或单一阈值替代韩立和南宫婉基于上下文的判断。机械门禁只用于保护授权、隐私、审计、回滚、测试和用户最终决策权。
