# 玻璃主题家族与皮肤分层架构蓝图

> 状态：历史方案，已于 2026-08-13 退役。

## 历史背景

本蓝图曾定义一套独立静态玻璃主题家族：共享 core、多个 skin、各 skin 的预览页面和统一静态导航入口。

历史方案包含 11 套深色或浅色玻璃皮肤，采用独立 CSS、HTML、manifest 和 SVG 资产组织。这套结构没有接入应用 Gradle 构建、`/sel/**` 运行资源或现行主题注册器，因此已经退出正式公共前端。

## 现行替代关系

当前唯一正式公共前端模块是：

```text
shared/frontend/sel-ui/
```

现行主题定义进入：

```text
shared/frontend/sel-ui/src/theme/packs/<theme-id>/
```

现行主题独占素材进入：

```text
shared/frontend/sel-ui/src/assets/themes/<theme-id>/
```

一个主题包应登记 manifest、深浅模式、主题 CSS 和自己的素材，并复用同一套 `sel*.js` 公共控件运行时。不同视觉体系通过主题包表达，不再建立第二套顶级主题源码树。

## 后续新增主题

新增主题时应：

1. 在 `sel-ui/src/theme/packs/<theme-id>/` 建立主题包。
2. 同时提供 `dark` 和 `light` 模式。
3. 在 manifest 中显式登记主题、模式、颜色和素材。
4. 将主题独占素材放入同 ID 的 `sel-ui/src/assets/themes/<theme-id>/`。
5. 接入应用的主题 manifest 加载顺序。
6. 执行公共主题契约、源码归属、构建和真实浏览器回归。

如果新设计需要不同的 DOM、行为或公共 API，它不再属于纯主题，应按公共控件治理流程新增或扩展正式控件。
