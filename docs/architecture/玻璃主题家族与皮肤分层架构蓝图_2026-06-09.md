# 玻璃主题家族与皮肤分层架构蓝图

## 1. 目的

本文件用于定义 `SELPLAT` 中 `glass-theme` 主题家族的标准分层方式、当前落地状态，以及后续新增皮肤时应遵循的结构约束。

最初的归并论证起点是两套玻璃风格皮肤：

- `indigo-amber-dark`
- `cyan-amber-dark`

截至当前，这套主题家族已经从两套初始皮肤扩展为 `11` 套皮肤，并配套统一的静态预览入口。

## 2. 当前结论

玻璃主题体系已经完成首轮收敛，当前应固定按“一个主题家族 + 多套皮肤”的模型继续扩展。

当前统一结论：

1. `glass-theme` 是正式主题家族目录。
2. 所有玻璃风格变体优先作为 `skin` 扩展，不再平铺成多个顶级主题目录。
3. 共享资产与基础样式进入 `core/`。
4. 每套皮肤独立放在 `skins/<skin-name>/`。
5. 主题家族根目录保留统一静态预览入口 `index.html`。

## 3. 当前已落地状态

当前 `glass-theme` 已包含以下 `11` 套皮肤：

- `indigo-amber-dark`
- `cyan-amber-dark`
- `emerald-aqua-dark`
- `violet-rose-dark`
- `crimson-amber-dark`
- `cobalt-mint-dark`
- `slate-lime-dark`
- `ivory-pearl-light`
- `champagne-blush-light`
- `frost-sky-light`
- `sage-cream-light`

当前预览入口已经固定为：

- 左侧可滚动皮肤列表
- 右侧常驻完整预览区
- 右侧预览区可独立滚动

这意味着旧的“皮肤墙 + 下方主预览”描述已经失效，后续文档和 AI 执行都应以当前双栏浏览模式为准。

## 4. 主题家族命名

当前主题家族目录采用中性英文命名：

```text
glass-theme
```

这样做的原因：

- 描述的是整套玻璃设计语言
- 不绑定宿主、考勤、权限、CRM 这类具体业务
- 后续可以稳定扩展更多皮肤

   │  ├─ crimson-amber-dark/

```text

├─ skin-tokens.css
├─ skin-components.css
├─ preview/
│  └─ index.html
└─ README.md
```

## 6. 命名规则

皮肤目录继续采用中性英文命名，优先使用：

```text
主色-辅色-dark
主色-辅色-light
```

这样命名的价值：

- 不绑定业务
- 能直接从名字看出色彩方向
- 后续新增皮肤时规则稳定

当前已落地示例：

- `indigo-amber-dark`
- `cyan-amber-dark`

## 7. 各层职责

### 7.1 `core/`

这里放玻璃主题家族的公共基座。

应该放：

- 共享背景资产
- 共享基础 token
- 共享基础组件样式
- 共享结构规则

不应该放：

- 某个皮肤独有的色值映射
- 某个业务独有的视觉语义
- 某个皮肤专用的预览页面

### 7.2 `skins/`

这里放皮肤目录。

每套皮肤负责：

- 颜色与 token 覆盖
- 皮肤自己的组件风格覆盖
- 皮肤级预览页面
- 皮肤说明文档

原则上，皮肤应扩展 `core`，而不是复制一整套 `core`。

### 7.3 `manifest/`

这里放主题家族元数据。

当前至少应维护：

- 家族 id
- 默认皮肤
- 支持皮肤列表

### 7.4 `index.html`

这里放主题家族统一预览入口。

当前职责固定为：

- 展示全部已接入皮肤的导航入口
- 允许快速切换当前皮肤
- 在统一位置展示完整预览

## 8. 当前预览策略

预览页仍然保留在皮肤层，每套皮肤继续维护自己的：

```text
preview/index.html
```

但主题家族根目录同时保留统一入口页：

```text
glass-theme/index.html
```

当前统一入口策略：

- 左侧列表只负责导航和当前皮肤定位
- 右侧区域只负责展示当前皮肤完整预览，并通过独立滚动条继续向下浏览
- 入口页同步展示皮肤标题、路径和说明

## 9. 深浅皮肤分组建议

当前皮肤可以按两类理解：

### 深色玻璃系

- `indigo-amber-dark`

- `emerald-aqua-dark`
- `violet-rose-dark`
- `crimson-amber-dark`

### 浅色轻玻璃系

- `ivory-pearl-light`

- `sage-cream-light`

后续如果入口页需要继续增强，优先考虑分组导航，而不是打散主题家族结构。

## 10. 后续新增皮肤的判断规则

如果满足以下条件，应新增 `skin`，而不是新增顶级主题家族：

- 设计语言仍然是玻璃风格
- 组件结构大体不变
- 主要变化集中在配色、通透度、强调感、亮暗关系

只有在以下情况下，才新增新的主题家族：

- 设计语言彻底变化
- 组件行为模型明显变化
- 已不属于玻璃主题范式

## 11. 当前与旧结构的关系

首轮重构已经完成。

当前状态是：

1. 正式入口只保留 `glass-theme`。
2. 初始两套皮肤已经并入 `glass-theme/skins/...`。
3. 更多深色与浅色皮肤已在同一主题家族下扩展完成。
4. 旧兼容残留目录已清理，不再作为消费入口存在。

因此后续新增皮肤时，不应再回到“顶级平铺多个主题目录”的做法。

## 12. 文档与修正联动要求

当主题系统发生新增皮肤、删除皮肤、重构预览入口等操作时，至少应同步检查：

- `shared/frontend/theme/glass-theme/manifest/theme-family.json`
- `shared/frontend/theme/glass-theme/README.md`
- `shared/frontend/theme/README.md`
- `shared/frontend/theme/glass-theme/index.html`
- `ai-standards/主题系统修正索引.md`
- `ai-standards/预览入口修正索引.md`

## 13. 一句话定版

`glass-theme` 已经是 `SELPLAT` 中正式落地的玻璃主题家族；后续应继续按“一个主题家族、多个皮肤、统一预览入口、共享 core 基座”的结构扩展，不再退回到多个顶级平铺主题目录。
