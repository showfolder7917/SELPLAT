# 当前系统编译说明规则

## 1. 适用范围

本规则适用于 `SELPLAT` 当前工作区内所有 Java / Gradle / VS Code 编译相关操作。

目的：

1. 防止后续 AI 或人工误把编译产物重新打散到模块本地目录
2. 防止串改当前已收口的 VS Code / Gradle 编译配置
3. 为后续排查 `bin` / 模块本地 `build` 是否属于异常重建提供统一判断口径

## 2. 当前正式编译口径

### 2.1 Gradle 正式输出目录

当前正式编译产物统一以根目录为准：

`C:\opt\workspace\SELPLAT\build`

但必须按模块路径继续分层，不能平铺混放。

示例：

- `C:\opt\workspace\SELPLAT\build\apps\uniauth\backend\...`
- `C:\opt\workspace\SELPLAT\build\shared\backend\common-core\...`

### 2.2 VS Code 当前启动 / 编译口径

当前 VS Code 工作区已经收口为：

1. 单工程启动前通过 `preLaunchTask` 先执行 Gradle 编译
2. `tasks.json` 中 `uniauth:classes` / `uniauth:run` 使用根目录 `gradlew(.bat)` 触发离线构建
3. 不再依赖 JDT 默认的“启动前强制本地编译”作为主链

### 2.3 当前默认编译命令

当前推荐的单模块编译命令：

```powershell
.\gradlew.bat --offline --console plain :apps:uniauth:backend:classes
```

当前推荐的单模块运行命令：

```powershell
.\gradlew.bat --offline --console plain :apps:uniauth:backend:run
```

## 3. 当前关键配置事实

### 3.1 根 `build.gradle`

当前根 `build.gradle` 已把所有子项目输出统一到根 `build/<project-path>`。

后续不得随意回退成模块各自写本地 `build`。

### 3.2 `.vscode/settings.json`

当前关键设置包括：

- `java.import.gradle.user.home = .gradle`
- `java.project.outputPath = build\java-bin`
- `java.autobuild.enabled = false`
- `java.debug.settings.forceBuildBeforeLaunch = false`

这代表当前策略是：

1. Gradle 用户目录统一到工程根 `.gradle`
2. 不再依赖 JDT 默认自动编译作为正式输出链
3. 运行 / 调试前通过显式 Gradle 任务保证 class 存在

### 3.3 `.vscode/tasks.json`

当前 `uniauth:classes` 是默认 build task，且必须继续使用离线 Gradle 命令。

### 3.4 `.vscode/launch.json`

当前 `UniauthBackendApplication` 启动项已绑定 `preLaunchTask = uniauth:classes`。

后续如果改启动配置，不得去掉这条前置编译链，除非同时提供新的、同等明确的 Gradle 前置编译方案。

## 4. 当前允许存在的目录

### 4.1 允许保留

- `C:\opt\workspace\SELPLAT\build`
- `C:\opt\workspace\SELPLAT\.gradle`
- `.vscode` 内与当前工作区配置一致的 JSON 文件

### 4.2 视为异常或历史残留

以下目录若重新出现，应优先判断为异常重建或历史残留：

- `C:\opt\workspace\SELPLAT\apps\uniauth\backend\bin`
- 各模块本地 `build`
  - `apps\build`
  - `apps\uniauth\build`
  - `shared\build`
  - `shared\backend\build`
  - `shared\backend\common-*\build`

## 5. 后续 AI 禁止事项

后续 AI 未经明确确认，不得执行以下动作：

1. 不得把 `build.gradle` 回退成模块各自写本地 `build`
2. 不得把 `.vscode/settings.json` 中的 `java.import.gradle.user.home` 改回 `${workspaceFolder}\.gradle` 之类会误建目录的写法
3. 不得随意移除 `launch.json` 里的 `preLaunchTask`
4. 不得把 `tasks.json` 的 Gradle 命令改回不带 `--offline --console plain` 的分散写法，除非有明确新方案
5. 不得把 `apps/.../bin` 或模块本地 `build` 当成当前正式编译目录
6. 不得在未验证的情况下宣称 “VS Code 已完全不再重建 bin”

## 6. 后续 AI 允许操作边界

后续 AI 可以做的事：

1. 在根 `build` 统一策略不变的前提下微调 `launch.json` / `tasks.json`
2. 在不恢复 JDT 默认本地输出链的前提下，优化 VS Code 启动体验
3. 清理异常重建的 `bin` / 模块本地 `build` 残留
4. 继续补充验证步骤和排查记录

## 7. 判断规则

如果后续又出现编译产物目录冲突，按以下顺序判断：

1. 看产物是否落在根 `build/<project-path>`
   - 若是，优先视为当前正式编译链
2. 看目录是否是模块本地 `bin`
   - 若是，优先视为 VS Code / JDT 本地输出
3. 看目录是否是模块本地 `build`
   - 若是，优先视为旧产物或异常重建

## 8. 推荐复核命令

### 8.1 构建验证

```powershell
.\gradlew.bat --offline --console plain :apps:uniauth:backend:classes
```

### 8.2 根 build 检查

```powershell
Get-ChildItem C:\opt\workspace\SELPLAT\build\apps\uniauth\backend
```

### 8.3 异常目录检查

```powershell
Test-Path C:\opt\workspace\SELPLAT\apps\uniauth\backend\bin
Test-Path C:\opt\workspace\SELPLAT\apps\build
Test-Path C:\opt\workspace\SELPLAT\shared\build
```

## 9. 当前人工复核口径

在本轮配置下，重启 VS Code 后应重点人工确认：

1. 打开工作区后是否自动重建 `apps/uniauth/backend/bin`
2. 执行 `UniauthBackendApplication` 启动项后是否只使用 Gradle 前置编译
3. 改动 Java 文件后是否仍满足你的实际开发节奏

若重启 VS Code 后 `bin` 仍然自动重建，则说明还存在未收口的 JDT 本地编译行为，后续应继续在 VS Code Java 设置层面排查，而不是回退根 `build` 统一策略。

## 10. 工程差异特别说明

### 10.1 为什么 `CPMAB081` 没有自动创建 `bin`

当前已确认：

- `C:\opt\bat\CPMAB081` 是独立的单体 Gradle 根工程
- VS Code 对它的导入路径更接近“标准独立 Gradle 工程”
- 当前未观察到 `CPMAB081\bin` 自动重建

### 10.2 为什么 `SELPLAT/apps/uniauth/backend` 会重建 `bin`

当前已确认：

- `apps/uniauth/backend` 不是工作区根工程，而是 `SELPLAT` 多模块 Gradle 工程中的一个子项目
- 该模块还是可直接启动的应用模块，当前 `launch.json` 中显式通过 `mainClass` / `projectName` 参与 VS Code Java 调试链
- 重建出来的目录结构是：
  - `bin/default`
  - `bin/main`
  - `bin/generated-sources/annotations`

这类结构应优先判断为 **VS Code Java 扩展 / Eclipse JDT LS / Buildship 的本地工程输出**，而不是 Gradle 正式产物。

### 10.3 后续 AI 的判断要求

后续若再次出现：

- `CPMAB081` 无 `bin`
- `SELPLAT/apps/uniauth/backend` 有 `bin`

不得直接据此判断：

1. `SELPLAT` 的 `build.gradle` 统一策略失效
2. `java.project.outputPath` 配置失效
3. Gradle 又回退到模块本地 `build`

正确判断顺序应为：

1. 先确认根 `build/apps/uniauth/backend/...` 是否仍正常生成
2. 再判断 `backend/bin` 是否为 JDT 本地输出
3. 最后再决定是否需要继续限制 VS Code Java 扩展行为
